# `evals/runs/` — 원시 실행 결과

`scripts/eval_prompt.py --run` 이 만든 **모델의 날것 응답**이 여기 쌓인다.

## 왜 커밋하나

**호출이 비싸다** — 한 판 14~20초 + 구독 한도. 15판이면 5분이다.

2026-08-27 에 자를 **두 번** 고쳤다 (화이트리스트로 · 축을 두 질문으로 갈라서).
두 번 다 **호출을 한 번도 안 하고** 15판을 다시 쟀다 — 원시 findings 가
`scratch/prompt_2x2.json` 에 남아 있었기 때문이다. 그게 없었으면 그날 작업이 불가능했다.

⚠️ 그건 **운이었다.** `scratch/` 는 `.gitignore` 대상이라 로컬에 우연히 남아 있었을 뿐이고,
새 세션이나 다른 머신에는 없다. 그래서 여기로 옮긴다 —
**측정은 재현 가능해야 하고, 재현의 재료는 원시 응답이다.**

구조 결정 (2026-08-27). 후보는 `scratch/` · `evals/runs/` · `fixtures/runs/`.
`fixtures/` 가 탈락한 이유: *"`evals/` → `fixtures/` 한 방향만"* 규칙이 있는데
평가의 산출물이 fixtures 로 들어가면 **화살표가 거꾸로 생긴다.**

## 여기 있는 것 / 없는 것

| | |
|---|---|
| **있다** | 모델이 뱉은 `findings` 원문 · `usage` · 지연 · 그 실행의 조건(meta) |
| **없다** | 채점 결과. **점수는 저장하지 않는다** — 자가 바뀌면 낡기 때문이다 |

점수를 파일에 박으면 `expected.yaml` 을 고쳤을 때 **두 숫자 중 어느 게 최신인지 알 수 없다.**
채점은 언제나 `--regrade` 로 그 자리에서 다시 계산한다.
📖 책 인쇄 219 — *"이 소형 저장소의 수치를 **영구적인 순위표로 간주하지 말 것**."*

## ⚠️ 돌리기 전에 이전 실행을 커밋한다

파일명은 조건에서 **계산**하므로 (D8) 같은 조건으로 다시 돌리면 **덮어쓴다.**
그래도 된다고 판단한 근거가 *"이력은 git 이 갖는다"* 였다 — **그 전제가 지켜져야 성립한다.**

```bash
git add evals/runs/ && git commit    # ← 먼저
uv run python scripts/eval_prompt.py run sample -k 3
```

📌 **2026-08-27 에 실제로 잃었다.** `sample__luna__k3.json` 첫 3판을 커밋하기 전에
같은 명령을 다시 돌려서 덮어썼다. 잃은 게 캐시 miss 3판이라 결론엔 영향이 없었지만,
값진 실행에서 같은 일이 나면 되돌릴 방법이 없다.
**결정이 틀린 게 아니라 전제가 안 지켜진 것이다.**

## 언제 지우나

`meta.model` 이 바뀌면 그 이전 결과는 **비교 대상이 아니다** (다른 모델의 성적표다).
지우지 말고 남겨두되, 표에 섞지 않는다 — 그래서 `meta` 가 파일마다 붙는다.
