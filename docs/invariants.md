# 불변식 (Invariants)

> 절대 깨면 안 되는 규칙. **"코드 규약"이 아니라 물리적으로 깨는 게 불가능하게 만드는 게 목표다.**
> 규칙을 잊을 수 있는 사람은 있어도, DB가 거부하는 건 아무도 못 뚫는다 [02:55:58].
> 이 파일도 `DONE.md`와 마찬가지로 **에이전트가 수정할 수 없다.**

---

## INV-1 — 모든 GitHub webhook payload는 서명 검증을 통과한다

출처 [02:23:42]

**어디서 강제되나**: `backend/webhook/app.py`, 어떤 처리보다도 먼저.

**왜**: 여기가 신뢰 경계다. 출처를 증명하지 못하면 **아무 일도 하지 않는다.** 검증 없는 웹훅 엔드포인트는 시스템으로 들어오는 열린 문이다.

**구현 주의**
- HMAC은 **raw bytes**로 계산한다. `request.json()`으로 파싱한 뒤 다시 `json.dumps()` 하면 공백·키 순서가 달라져 절대 안 맞는다. `await request.body()`를 쓸 것.
- 비교는 `hmac.compare_digest()` — 타이밍 공격 방지.
- 검증 실패는 **이유와 무관하게 항상 같은 400.** 응답을 획일화해서 공격자에게 신호를 주지 않는다 [02:39:42].
- 서명이 통과한 뒤 본문이 깨진 경우도 **400이지 500이 아니다.** HMAC 통과 = 발신자가 공유 비밀을 가진 인증된 호출자. 인증된 호출자가 보낸 잘못된 본문은 클라이언트 오류다. 500을 뱉으면 서버 모니터링에 헛경보가 뜬다.

## INV-2 — 모든 webhook delivery는 delivery ID를 멱등성 키로 써서 중복 제거된다

출처 [02:23:42]

**어디서 강제되나**: M1에선 인프로세스 메모리(의도된 임시), M4부터 Redis.

**왜**: GitHub은 같은 배달을 재시도한다. 중복 제거가 없으면 같은 PR에 리뷰가 두 번 붙는다.
서명(INV-1)과 멱등키를 발표자는 **"OTP 확인하듯 독립된 두 겹의 방어"**로 비유했다 [01:30:05].

**주의**: M1의 인메모리 dedup은 프로세스 재시작을 못 넘긴다. **이건 알고 하는 임시 선택**이고, M4에서 Redis로 교체한다 [02:42:55]. 알고 하는 타협은 기록해두면 부채가 아니다.

## INV-3 — 모든 스페셜리스트 에이전트 finding은 confidence와 rationale을 갖는다

출처 [02:23:42]

**어디서 강제되나**: `Finding` pydantic 스키마에서 필수 필드로. 스키마가 거부하게 만든다.

**왜**: 이게 없으면 confidence 게이트(M8)가 작동할 수 없고 — 즉 **이 시스템의 존재 이유가 사라진다.**
그리고 근거 없는 지적은 리뷰가 아니라 소음이다. 시니어는 "이거 좀 이상한데요"가 아니라 "40번 줄에서 user_input이 그대로 쿼리 문자열에 들어갑니다"라고 말한다 [00:41:04].

**검사 방법**: `confidence`가 항상 0.9 같은 상수로 나오면 **필드는 있지만 불변식은 깨진 것**이다. 값이 실제로 분포하는지 확인할 것.

## INV-4 — `agent_events`에 대한 `UPDATE` / `DELETE`는 DB 레벨에서 하드 거부된다

출처 [02:55:58]

**어디서 강제되나**: `migrations/` 안의 **트리거**. 애플리케이션 코드가 아니다.

**왜**: 감사 추적이 시스템의 유일한 증거다. 행을 바꿀 수 있으면 트레이스를 믿을 수 없고, "왜 이렇게 판단했냐"는 다툼이 붙었을 때 아무것도 증명하지 못한다.

**구현 함정 3개**
1. **`CREATE RULE`은 하이퍼테이블에서 안 된다** [03:00:45]. Postgres RULE은 쿼리 재작성 단계에서 도는데, 하이퍼테이블은 데이터를 여러 chunk 테이블로 흩뿌리고 재작성 규칙을 지원하지 않는다. → **트리거를 쓸 것.**
2. **`TRUNCATE`는 DELETE 트리거를 우회한다** [03:02:54]. TRUNCATE는 DELETE의 반복이 아니라 별개 실행 경로를 가진 별개 명령이다. row-level 트리거가 발화하지 않는다. → **statement-level `BEFORE TRUNCATE` 트리거를 따로** 걸 것.
3. **테스트 예외를 만들지 않는다** [02:57:26]. 스모크 테스트가 넣은 행도 영원히 남는다. 테스트용 탈출구는 곧 모두를 위한 탈출구가 되고, 그 순간 감사 추적의 신뢰가 무너진다. 테스트는 별도 스키마/DB에 두거나 `is_test` 컬럼으로 필터링할 것.

> 함정 2를 찾은 건 빌더가 아니라 **독립 검증자**였다. 이게 `DONE.md`의 검증 절차가 존재하는 이유다.

## 불변식을 추가하고 싶을 때

추가는 사람만 한다. 그리고 추가하기 전에 물어볼 것: **"이걸 DB나 타입 시스템이 강제하게 만들 수 있나?"**
못 하면 그건 불변식이 아니라 그냥 좋은 습관이다. 좋은 습관은 이 파일이 아니라 `docs/adr/`에 적는다.
