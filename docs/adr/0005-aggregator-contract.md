**날짜**: 2026-08-18
**상태**: **잠정 결정 — 코드에 들어감** (2026-08-28). 실측이 후보표 절반을 죽였다 (아래)
**영향받는 것**: M6 `backend/agents/aggregator.py` · M8 게이트 입력
**시점**: ~~M5 브리핑 직전~~ → **M6 브리핑 직전**

> **왜 미뤘나** (2026-08-18, 사용자 지적):
> 원래 근거는 "M5 state 의 findings 모양이 여기 걸린다" 였는데, **그 모양은 이미 나왔다** —
> `{findings, completed, failed}` ([Lesson 06](../../learning/lessons/0006-nobody-looked.html) 3절).
> 그리고 M5 는 `03-build-plan.md` 가 **"노드가 sleep + 더미 Finding 만 뱉어도 됨"** 이라고 못박은
> 배선 단계라 **합칠 중복이 생기지 않는다.** 지금 dedup 키를 정하면 실측이 아니라 상상으로 정하는 것이고,
> M6 에서 진짜 findings 네 세트를 보고 정하면 근거를 갖고 정할 수 있다.
> 되돌리기 비용이 0 이라 미루는 대가도 0 이다 — 저스트-인-타임이 정확히 이 경우를 위한 원칙이다.

**되돌리기 비용**: 0 (문서 한 문단). M6 에서 코드가 되면 그때부터 비용이 생긴다

## 맥락 — 왜 이게 결정이어야 하나

애그리게이터(⑤)는 **정리**만 한다. 판단은 게이트(⑥)가 한다.
그런데 "정리"에도 버리는 동작이 들어간다 — 둘을 하나로 합치면 **하나는 사라진다.**
무엇을 사라지게 할지가 판단이고, 그래서 계약이 필요하다.

### 실측 근거 (M0, `PLAN.md` G-M0-3)

> 같은 `(file, line, category)` 에 **`severity` 만 다른** 중복 finding 이
> **에이전트 하나의 한 번 호출**에서 생성됨.

에이전트 하나가 그랬다. M6 에서 넷으로 갈리면 **같은 줄을 넷이 각자 지적**하는 경우가 더해진다.

### 이미 확정된 제약

| | 어디서 | 무엇 |
|---|---|---|
| `category` 는 **자유 태그** | `004_truth.sql:150` | CHECK 없음. `'sql-injection'` 과 `'sqli'` 가 다른 문자열이면 다른 값이다 |
| `severity` 는 **닫힌 5개** | `004_truth.sql:141` | critical / high / medium / low / informational |
| 모든 finding 에 rationale | INV-3 | 합칠 때 한쪽 rationale 이 사라진다 |
| M6 완료 판정 ④ | `03-build-plan.md` | "두 에이전트가 같은 줄을 지적했으면 애그리게이터 출력에선 **하나로 합쳐짐**" |

## 결정 1 — dedup 키: 무엇이 같으면 "같은 지적"인가

| 후보 | 합쳐지는 것 | 대가 |
|---|---|---|
| **A** `(file, line)` | 같은 줄이면 무조건 하나 | `app.py:16` 의 SQL 인젝션과 "테스트 없음" 이 **한 개로 뭉개진다** |
| **B** `(file, line, category)` | 줄 + 종류가 같아야 | `'sql-injection'` vs `'sqli'` 는 **다른 것으로 남는다** (category 가 자유 태그라서) |
| **C** `(file, line, category, agent_type)` | 에이전트까지 같아야 | security 와 testing 이 같은 줄을 지적해도 **안 합쳐진다** |
| **D** LLM 에게 "이 둘 같은 지적이냐" 묻기 | 뜻이 같으면 합쳐짐 | 비결정적 · 호출 비용 · **재현 불가능한 완료 판정** |

**고르는 기준 두 개**:
1. M6 완료 판정 ④를 통과하는가 — 통과 못 하는 후보가 하나 있다
2. 합쳐서 **사라지는 것**이 진짜 중복인가, 다른 문제인가

⚠️ 틀리면 뭐가 깨지나: 너무 넓으면 **지적이 조용히 사라진다**(게이트가 못 봄).
너무 좁으면 같은 줄에 코멘트가 여러 개 달린다(시끄럽지만 안 위험).
**두 오류의 방향이 다르다** — 어느 쪽으로 틀리는 게 나은지가 선택의 절반이다.

## 결정 2 — 충돌 시 무엇이 남나

두 finding 이 같은 키인데 값이 다를 때. **필드마다 답이 다를 수 있다.**

### 2-a. `severity` 가 다르면

후보: 더 심각한 쪽 / 더 확신 높은 쪽 / 둘 다 남김 / 다수결

기준: 게이트는 `critical` 을 보면 사람에게 보낸다.
**`critical` 을 버리고 `medium` 을 남기면 사람에게 갈 것이 자동 게시된다.**
반대 방향의 실수(medium 을 버리고 critical 을 남김)는 시끄럽기만 하다.

### 2-b. `confidence` 는 — 여기가 진짜 빈칸이다

severity 를 A 쪽에서 가져왔는데 confidence 는 어디서 가져오나?

```
finding ①  severity=critical  confidence=0.40   ← severity 는 이쪽이 남는다
finding ②  severity=medium    confidence=0.95
```

후보: 남긴 쪽의 값 / 최댓값 / 최솟값 / 평균

⚠️ 최댓값을 쓰면 위 예에서 **`critical` + `0.95`** 라는, **아무도 말한 적 없는 finding** 이 생긴다.

### 2-c. `rationale` 은 (INV-3 이 걸린다)

후보: 남긴 쪽 것 / 둘을 이어붙임 / 확신 높은 쪽 것

기준: 사람이 HITL 큐에서 읽는 글이다. 그리고 M8 게이트는 rationale 을 **안 읽는다**
(`PLAN.md` G-M0-4). 즉 이건 **사람만을 위한 필드**다.

## 결정 3 — 애그리게이터는 코드인가 LLM인가

| | 장점 | 대가 |
|---|---|---|
| **코드** | 결정론적 · 무료 · 완료 판정이 재현됨 | "뜻은 같은데 문자열이 다른" 중복을 못 잡는다 |
| **LLM** | 의미 단위 병합 · 요약까지 | 비결정적 · 호출 하나 더 · **트러스트 바운더리가 하나 늘어난다** |

⚠️ 마지막 항목이 핵심이다. finding 의 `rationale` 에는 **diff 에서 온 문자열이 섞여 있다**.
그걸 LLM 에 다시 먹이면 [Lesson 02](../../learning/lessons/0002-untrusted-diff.html) 의
간접 인젝션 경로가 **애그리게이터에도 생긴다**. 스페셜리스트에서 한 번 막은 것을 또 막아야 한다.

## 결정 4 (선택) — `overall confidence` 는 누가 계산하나

`CLAUDE.md` 다이어그램은 ⑤를 "중복 제거 + **전체 확신도**" 라고 적었다.
그런데 그 숫자를 쓰는 건 게이트뿐이다.

- **애그리게이터가 계산** → 다이어그램대로. 게이트는 받은 숫자만 비교
- **게이트가 계산** → 애그리게이터는 findings 만 넘긴다. **정책이 한곳에 모인다**

기준: "무엇이 존재하는가"(계약)와 "그중 뭘 통과시키나"(정책)의 경계.
`0.6` 이 게이트에만 사는 것과 **같은 종류의 질문**이다.

## ⚠️ 실측이 이 문서의 후보표 절반을 죽였다 (2026-08-28)

미뤄둔 게 값을 했다. **관점 넷을 같은 diff 에 돌린 첫 실측** (`fixtures/sample.diff`, 각 1판):

```
security   [high    ] sql-injection  api/users.py:17  conf=1.00
quality    [critical] sql-injection  api/users.py:17  conf=0.99
           [medium  ] resource-leak  api/users.py:15  conf=0.97
testing    [critical] sql-injection  api/users.py:15  conf=1.00
           [medium  ] resource-leak  api/users.py:12  conf=0.95
           [low     ] missing-test-coverage :16       conf=0.98
docs       [critical] sql-injection  api/users.py:17  conf=1.00
           [medium  ] resource-leak  api/users.py:18  conf=0.98
```

### ① `line` 이 관점마다 다르다 → **결정 1 의 후보 A·B·C 가 전부 죽는다**

같은 `resource-leak` 을 `:15` · `:12` · `:18` 로 가리켰다. 셋 다 `line` 을 키에 쓰므로
같은 결함이 두세 개로 남고, **M6 완료 판정 ④("같은 줄은 하나로 합쳐짐")를 원리적으로 통과 못 한다.**

⚠️ 더 나쁜 사실: **@@ 헤더로 계산한 정답은 `:14`(resource-leak) 와 `:16`(sql-injection) 이다.**
넷 다 틀렸고, `fixtures/expected.yaml` 의 `what_it_is` 도 *"SQL 인젝션(users.py:17)"* 이라 적혀 있다 —
**사람도 같이 틀렸다.** D1 이 `line` 을 매칭 축에서 뺀 덕에 채점은 통과했고,
그래서 이 오답이 15판 내내 안 잡혔다. *안 재기로 한 축은 틀려도 조용하다.*

### ② 관점을 갈랐는데 경계가 안 갈렸다 → **결정 4 가 위험해졌다**

`docs` 프롬프트는 *"처음 보는 사람이 답을 못 찾을 질문이 남는가"* 인데 문서 얘기를 한 마디도 안 했다.
넷의 `confidence` 가 `1.00·0.99·1.00·1.00` 이라 **어떻게 합쳐도 1.0 근처**가 나오고,
그건 "넷이 확신했다"처럼 읽힌다. 📖 인쇄 320 — *"같은 모델이 비슷한 컨텍스트에서 생성한 여러 검토
의견을 자동으로 독립 증거로 간주해서는 안 된다."*

### ③ 채널을 못 고른다 → **결정에 없던 항목이 하나 늘었다**

`state["findings"]` 에는 `operator.add` 리듀서가 붙어 있다. 실측:
`_aggregate` 가 `{"findings": [합친 것]}` 을 돌려주면 **또 더해진다.** 덮어쓰기라는 동작이 없다.
→ 애그리게이터는 **새 채널(`merged`)로만** 나갈 수 있다. 취향이 아니라 물리적 제약이다.
덤: 원본이 남으니 **무엇을 버렸는지 추적된다** (INV-4 의 정신).

**`len(sources)` 를 신뢰도로 쓰지 않는다.** 넷이 다 잡았다는 건 커버리지 관측이지

⚠️ **책이 안 닿는 곳**: 10.5 는 에이전트가 서로 **메시지를 주고받는** 구조를 전제한다(귓속말 게임).

전파(10.5.2)가 아니라 **동시 발생**(10.5.3)이고, 그건 합치는 순간에만 드러난다.
그래서 책의 처방(교차 검증자를 하나 더 두기)을 그대로 쓰지 않는다 —
우리한테 필요한 건 검증자가 아니라 **정직한 출처 기록**이다.

### ⚠️ 계약이 **틀렸던 것 둘** (2026-08-28, 자가 검증에서 발견)

**① `pick_representative` 가 완전 동률에서 비결정적이었다.**
정렬 키가 `(severity, -confidence, agent_type 순서)` 셋뿐이라, **한 관점이 같은 결함을 두 번
뱉으면** 셋이 전부 같아져 입력 순서가 결과를 바꿨다. 그건 상상이 아니다 —
M0 에서 관측됐다(`PLAN.md` G-M0-3). 그리고 리듀서가 쌓는 순서는 **노드 완료 순서라 비결정적**이다.
→ `(line, rationale)` 을 마지막 타이브레이커로 추가. **의미가 있어서가 아니라 안정적이라서**다.
⚠️ **판정 ⓪(셔플 5회)가 이걸 못 잡았다** — 측정 데이터에 완전 동률이 없었기 때문이다.
   **판정이 통과한 범위가 판정문의 주장보다 좁았다.** 동률 케이스를 판정에 추가했다.

**② `by:` 축이 `all([]) == True` 구멍을 열었다.**
`sample` 의 `must_catch` 는 security·quality 것뿐이라 **docs·testing 에겐 요구가 0개**다.
그래서 `caught == []` 이고 `all([]) == True` — **findings 가 아예 0개인 판이 통과했다**(실측).
→ `passed` 는 안 바꿨다(요구가 없는데 벌하는 건 더 틀렸다). 대신 `RunGrade.graded_items` 를
  더하고 표가 **"이 숫자는 「지어내지 않았나」만 잰 것"** 이라고 말하게 했다.
  security 의 `2/3` 와 docs 의 `3/3` 은 **다른 양**이고, 같은 칸에 찍으면 6개월 뒤
  *"docs 가 security 보다 낫다"* 로 읽는다.
