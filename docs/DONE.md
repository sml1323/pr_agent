# DONE — "완료"의 고정 정의

> ⛔ **이 파일은 읽기 전용이다.** 코딩 에이전트는 이 파일을 수정할 수 없다.
> 마찰을 만나면 에이전트는 "완료"의 정의를 자기한테 편한 쪽으로 슬쩍 재정의한다 [02:02:24].
> 그걸 막는 게 이 파일의 유일한 존재 이유다. 정의를 바꾸려면 사람이 직접 고치고, 왜 바꿨는지 `docs/adr/`에 남긴다.

---

## 이 시스템이 하는 인지적 과업

시니어 엔지니어가 PR을 리뷰할 때 머릿속에서 하는 일을 대신한다.
**단, 목표는 "리뷰 자동화"가 아니라 selectivity(선별성)** [00:38:27] — 시니어의 주의력을 아껴주는 것.

명확히 처리 가능한 건 시스템이 처리하고, **애매한 건 사람에게 넘긴다.** 이 문장이 지켜지지 않으면 나머지가 다 돌아가도 실패다.

## 입력

GitHub webhook의 `pull_request` 이벤트 (opened / synchronize).
**이 입력은 신뢰할 수 없다.** 두 가지 이유로:
1. 아무나 우리 엔드포인트에 위조 요청을 쏠 수 있다 → HMAC 서명 검증
2. PR diff는 **PR을 열 수 있는 아무나가 쓴 텍스트**다 [02:07:26] → 프롬프트 인젝션 벡터

## 자율성 수준

**레벨 3 — "사람이 예외를 처리한다"** [00:24:29]

쉽고 확실한 건 시스템이 자동 게시하고, 이상치와 낮은 confidence는 사람 큐로 간다.
완전 자율(레벨 4~5)은 **선택하지 않았다.** 잘못된 리뷰 코멘트는 되돌릴 수 있지만, 보안 취약점을 공개 PR 스레드에 게시하는 실수는 되돌릴 수 없기 때문 [00:11:59].

## 실패 허용도

| 실패 | 허용? | 대응 |
|---|---|---|
| 놓친 이슈 (false negative) | **허용** | 사람 리뷰어가 여전히 존재함. 시스템은 사람을 대체하지 않음 |
| 잘못된 지적 (false positive) | **제한적 허용** | 신뢰를 갉아먹음. confidence 게이트로 걸러냄 |
| critical 보안 건을 공개 게시 | **절대 불가** | 별도 비공개 경로. 자동 게시 금지 |
| 같은 PR에 리뷰 중복 게시 | **절대 불가** | 멱등성(INV-2) |
| 근거 없는 finding | **절대 불가** | rationale + confidence 필수 (INV-3) |
| 감사 추적 유실 | **절대 불가** | append-only 이벤트 스파인 (INV-4) |

## 전 구간에 걸리는 엔지니어링 규칙

영상이 `DONE.html`에 못 박은 것들 [02:21:32]. 마일스톤과 무관하게 항상 적용된다.

1. **의존성 방향을 명시한다.** `webhook → queue → orchestration → agents → retrieval`. 역방향 import 금지.
2. **모든 외부 호출에는 타임아웃이 있다.** LLM, DB, GitHub API, 임베딩 — 예외 없음. 타임아웃 없는 호출 하나가 오케스트레이터 전체를 멈춘다 [01:05:02].
3. **LLM 출력은 위협 모델에 대고 검증한다.** 구조화 스키마 강제 + 게이트 통과. LLM이 뱉은 걸 그대로 GitHub에 붙이지 않는다.
4. **모든 마일스톤은 별도 에이전트가 검증한다.** 만든 쪽이 검증하지 않는다 (아래 참조).
5. **모든 마일스톤에는 돌려볼 수 있는 데모 명령이 하나씩 있다.** "됐습니다"는 증거가 아니다.

## 누가 코드를 쓰나

**사람이 직접 타이핑한다** ([ADR 0002](adr/0002-implementation-mode.md)). 코딩 에이전트는 구현하지 않는다.
Claude의 역할은 브리핑 / 막혔을 때 힌트 / 독립 검증 / 개념 설명 — 그리고 순수 보일러플레이트뿐이다.

영상은 반대로 에이전트한테 시키지만, 이 프로젝트는 학습 비중이 **설계 사고 60%**라 방식을 다르게 간다.
**설계는 코드에서 저항할 때 이해된다.**

## 마일스톤 완료 판정 절차

이 세 단계를 **전부** 통과해야 완료다. 하나라도 빠지면 미완료.

1. **데모 명령이 실제로 돈다** — `docs/PLAN.md`에 적힌 그 명령을, 그대로 터미널에서.
2. **독립 검증을 통과한다** — 새 세션에게 목표·성공 기준·불변식만 준다. **빌더의 추론 과정은 절대 주지 않는다** [02:37:06].
   빌더의 맥락을 읽은 검증자는 빌더의 맹점을 그대로 물려받기 때문이다.
   검증자 프롬프트: *"너는 독립 리뷰어다. 코드를 쓰지 마라. 빌더의 주장을 참이라고 가정하지 마라. 직접 실행해서 확인해라."*
3. **이해도 체크를 통과한다** — 내가(사람이) 세 유형의 질문에 답할 수 있다 [03:00:45]:
   - **설계 근거**: 왜 이 방식인가? (예: 왜 RULE이 아니라 트리거인가)
   - **엣지 케이스**: 뭐가 이걸 우회하나? (예: TRUNCATE는 DELETE 트리거를 우회한다)
   - **변경 영향**: 이걸 바꾸면 어디가 깨지나? (예: 임베딩 차원을 바꾸면?)

   답을 못 하면 **코드가 돌아도 미완료다.** 이해 못 한 코드는 내 코드가 아니다.

> 영상에서 실제로 일어난 일: 빌더 에이전트가 M1 완료를 선언했는데, 독립 검증자가 500 크래시를 잡아냈다 [02:38:39].
> 그리고 코드가 존재하기도 전에 변경 영향 질문이 임베딩 차원 불일치를 잡아냈다 [03:03:59].
> 이 두 개가 절차 2·3의 값어치를 증명한다.

## 이 프로젝트의 범위

**M0 ~ M8까지.** M8은 선별(자동 게시 vs 사람 큐)이 실제로 도는 지점이고, 이 시스템의 존재 이유가 실현되는 곳이다.
M9~M12(신뢰성·비용관측·평가·피드백루프)는 **설계 문서로만** 남기고 구현하지 않는다.

범위를 늘리려면 이 파일을 사람이 직접 고친다. 에이전트가 "이왕 하는 김에"로 넘어가는 건 금지.

## 이 프로젝트가 아닌 것

- 프로덕션 배포 (Railway는 선택)
- 예쁜 대시보드 (psql 쿼리로 충분. 영상도 "여기 돈·토큰 쓰지 마라"고 못 박음 [02:09:32])
- 여러 언어 지원 (테스트 레포 하나면 충분)
- 성능 최적화
