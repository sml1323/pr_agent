## 마일스톤별 기록

각 마일스톤을 끝낼 때 아래 형식으로 채운다. 빈 칸을 남기지 말 것 — 특히 "알려진 구멍".

### M0 — diff → Finding JSON  🔵 데모 통과, 독립검증 대기

- **목표**: `.diff` 하나 → 구조화된 Finding 배열. 목적은 시스템 전체를 관통하는 **계약(Finding 스키마)을 손에 쥐는 것**.
- **토큰 예산**: 호출당 약 **2,000~2,400 in / 200~650 out** (`gpt-5.4-nano`). 반복 호출 시 프롬프트의 약 87%가 캐시됨(`cached_tokens=1792/2049`). 총 실행 8회, 비용 무시 가능 수준.
  ⚠️ 한 번 **13,440 out**이 나온 적 있음 — 같은 입력, 같은 모델. 아래 구멍 참조.
- **데모 명령**: `uv run python scripts/demo_m0.py fixtures/sample.diff`
- **통과 기준**: 모든 항목에 `confidence`(0~1)·`rationale`·`file`·`line`이 비어있지 않음. `rationale`이 "이거 좀 이상함"이 아니라 "40번 줄에서 user_input이 그대로 쿼리에 들어감" 수준. **`confidence`가 항상 같은 값이면 실패 취급.**
- **데모 결과 (2026-07-28)**: 4개 판정 전부 PASS.
  finding 4개 · `agent_type` 넷 모두 등장 · `confidence [0.6, 0.7, 0.85, 1.0]` · severity 4단계.
  심어둔 SQL 인젝션을 `critical`로 검출.
- **만든 것**: `backend/agents/schema.py`(Finding·ReviewResult) · `backend/agents/base.py` · `scripts/demo_m0.py` · `fixtures/{sample,sample_injected,sample_emotional}.diff`
- **독립 검증 결과**: **(미실시)** — 새 세션에서 수행할 것
- **이해도 체크**:
  - **설계 근거** (severity와 confidence를 왜 분리?) — ❌ 답 못 함. 설명 후 이해.
    핵심: 두 축이 **각각 독립적으로** 에스컬레이션을 트리거한다. 합치면 "critical인데 확신 30%"를 표현할 수 없다.
  - **엣지 케이스** — ✅ **감정 호소/사회공학**을 스스로 제시. 프롬프트의 명시적 패턴 4개 어디에도 없는 벡터.
    실제 테스트 결과 이번에는 방어됨(모델이 의도를 일반화). 다만 **관측이지 보장이 아님.**
  - **변경 영향** (게이트 임계값 0.6→0.5) — ❌ 답 못 함. 설명 후 이해.
    핵심: **고칠 곳이 게이트 상수 한 군데뿐**이라는 것 자체가 M0에서 정책을 스키마·프롬프트에서 뺀 성과.
  - → M8 완료 후 3번을 **다시 물을 것.** 지금은 게이트가 없어 상상으로 답해야 하는 상태.

- **알려진 구멍**:

  | | 증상 | 어디서 메우나 |
  |---|---|---|
  | **G-M0-1** | `line` 번호가 **체계적으로 앞섬**. 한 파일 안에서는 일정(2~3줄), 파일마다 편차. `@@` 계산 규칙을 프롬프트로 줘도 남음 | **M7** — 실제 파일을 컨텍스트에 넣어 세지 않게 |
  | **G-M0-2** | `finish_reason` 미체크. `length`로 잘려도 `parsed`가 채워져 통과. 잘린 rationale이 완료 판정 ②를 PASS로 통과한 사례 있음 | **M6** |
  | **G-M0-3** | 같은 `(file, line, category)`에 `severity`만 다른 **중복 finding**. 에이전트 하나가 한 번의 호출에서 생성 | **G6** (M5 브리핑) — 답의 절반은 이미 나옴: **더 심각한 쪽을 남긴다** |
  | **G-M0-4** | finding이 독립 항목이 안 되고 **다른 finding의 rationale에 흡수**됨. 게이트는 rationale을 안 읽으므로 신호가 도달 못 함 | **M6** — 에이전트 4개 분리 |
  | **G-M0-5** | 같은 입력에 출력 토큰 **277 → 13,440 → 440** 요동. 비용 예측 불가 | M9 (범위 밖) — 예산 가드 |
  | **G-M0-6** | 프롬프트 강조가 **제로섬**. 인젝션 규칙을 강화하니 4분류 검토가 밀려 finding이 4→1개로 감소 | **M6** — 관심사 분리의 실측 근거 |
  | **G-M0-7** | 인젝션 방어가 **관측이지 보장이 아님.** 프롬프트를 바꿔도 왜 좋아졌는지 잴 수단이 없음(G13) | **M8** — G3(근거 부족 분기)·G4(출력 가드레일) |

## 완료 절차 (매 마일스톤 반복)

`docs/DONE.md`의 3단 판정을 그대로 따른다.

1. **데모 명령 실행** — 위 표의 명령을 그대로.
2. **독립 검증** — 새 세션 열고 이 프롬프트만 준다. **빌더 세션의 대화 내용은 절대 붙여넣지 않는다.**

   ```
   너는 독립 리뷰어다. 코드를 쓰지 마라. 빌더의 주장을 참이라 가정하지 마라.
   목표: <마일스톤 목표 한 문장>
   성공 기준: <데모 명령 + 통과 기준>
   불변식: docs/invariants.md
   직접 실행해서 확인하고, 무엇이 위험한지 말해라.
   ```

   성공 기준을 "돌아가나"가 아니라 **"어떤 불변식이 위험한가"**로 물을 것 [02:57:57].
3. **이해도 체크** — 세 질문에 내가 답한다. 답 못 하면 코드가 돌아도 미완료 [03:00:45].
