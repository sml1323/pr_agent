# WORKFLOW — 세션 운영 방법

> **코드는 내가 직접 친다.** 에이전트는 대신 쓰지 않는다 ([ADR 0002](adr/0002-implementation-mode.md)).
> 영상은 에이전트한테 구현을 시키지만, 이 프로젝트의 목표는 설계 사고 체득(60%)이라 방식을 다르게 간다.

---

## 마일스톤 하나의 흐름

```
① 브리핑 (Claude) → ② 내가 구현 → ③ 자가 검증 → ④ 독립 검증 (Claude) → ⑤ 이해도 + 마무리
```

②가 대부분의 시간이고, 나머지는 짧다.

---

## ① 브리핑 — 시작 전 정렬

새 세션에서:

```
docs/CURRENT.md, docs/DONE.md, docs/invariants.md 를 읽어라.
그 다음 docs/03-build-plan.md 에서 M0 섹션만 읽어라.

나는 이 마일스톤을 직접 구현한다. 코드를 쓰지 마라.
다음만 정리해라:
1. 이번에 만드는 게 뭔지 (한 문단)
2. 왜 그 모양인지 — 설계 근거
3. 어떤 순서로 손대면 좋을지
4. 내가 모를 만한 개념 (있으면 짧게)
5. 이번 마일스톤이 건드리는 불변식
```

**Claude가 하는 것**: 설명, 순서 제안, 개념 정리, 함정 미리 알려주기
**Claude가 안 하는 것**: 코드 작성, 파일 생성

## ② 내가 구현

막히면 Claude한테 물어보되, **답을 바로 받지 말고 단계를 밟는다**:

| 상황 | 이렇게 물어봐 |
|---|---|
| 어디서 시작할지 모름 | "이거 어떤 순서로 접근해?" |
| 에러가 남 | "이 에러 무슨 뜻이야?" (코드 말고 원인) |
| API를 모름 | "pgvector에서 코사인 유사도 연산자 뭐야?" |
| 설계가 헷갈림 | "왜 여기서 X가 아니라 Y지?" |
| 30분 이상 막힘 | "힌트 줘 — 답 말고" → 그래도 안 되면 답 |

**바로 답을 받으면 그 부분은 안 배운 것.** 30분 룰을 지킬 것.

> Claude가 코드를 던지려고 하면 막는다. 설명은 받되, 타이핑은 내가.
> 예외: 순수 보일러플레이트(`.env.example`, `pyproject.toml` 등)는 받아도 됨. 배울 게 없는 것들.

## ③ 자가 검증

`docs/PLAN.md`의 데모 명령을 **내가 직접** 돌린다. 통과하면 ④로.

## ④ 독립 검증

**새 세션을 연다.** 구현하면서 대화했던 세션을 이어 쓰면 안 된다 — 내 설명을 들은 검증자는 내 맹점을 그대로 물려받는다 [02:37:06].

```
너는 독립 리뷰어다. 코드를 쓰지 마라. 내 주장을 참이라고 가정하지 마라.

목표: <마일스톤 목표 한 문장>
성공 기준: <데모 명령 + 통과 기준>
불변식: docs/invariants.md 를 읽어라.

직접 실행해서 확인하고, 어떤 불변식이 위험한지 말해라.
```

**주는 것**: 목표, 성공 기준, `invariants.md`, 코드
**절대 안 주는 것**: 구현 세션 대화, 내가 쓴 설명, "이렇게 해결했어" 같은 요약

질문을 **"돌아가나"가 아니라 "어떤 불변식이 위험한가"**로 던지는 게 요점 [02:57:57]. 전자는 "네 돌아갑니다"를 부르고, 후자는 증거를 부른다.

> 값어치의 증거 (영상에서 실제로 일어남): 빌더가 M1 완료를 선언했는데 검증자가 **500 크래시**를 잡아냈고 [02:38:39], 코드가 존재하기도 전에 변경영향 질문이 **임베딩 차원 불일치**를 잡아냈다 [03:03:59].

**내가 직접 짜면 이 단계가 더 중요해진다.** 에이전트가 짤 땐 "이 코드 이해했나"를 검증하지만, 내가 짜면 이해는 이미 됐고 대신 **내가 못 본 구멍**을 찾는 게 목적이다. 자기 코드의 맹점은 자기가 제일 못 본다.

## ⑤ 이해도 + 마무리

세 질문에 답한다 [03:00:45]. 직접 짰으면 1·2번은 쉽게 나오는데, **3번이 진짜 시험**이다.

1. **설계 근거** — 왜 이 방식인가?
2. **엣지 케이스** — 뭐가 이걸 우회하나?
3. **변경 영향** — 이걸 바꾸면 어디가 깨지나? ← 여기서 막히면 아직 시스템으로 안 보고 조각으로 보는 것

그리고 파일 갱신:

```
M0 완료. 다음을 갱신해라 (코드는 건드리지 마라):
- docs/PLAN.md — M0 상태, 독립검증 결과, 알려진 구멍
- docs/CURRENT.md — 지금 뭐가 살아있고 뭐가 스텁인지, 다음 한 걸음
- 새 결정을 내렸으면 docs/adr/ 에 추가
```

**"알려진 구멍"을 정직하게 적는 게 제일 중요하다.** 영상은 M1 끝내고 "Tiger 프로비저닝 미완, 스텁 큐를 Redis로 교체 필요"를 그대로 적었다 [02:47:23].

## 왜 이렇게까지 하나

한 줄로: **상태를 컨텍스트 창이 아니라 디스크에 두기 위해서** [02:46:02].

세션이 끊기든, 컨텍스트가 날아가든, 내일 다시 열든 — `CURRENT.md` 한 장으로 콜드 스타트가 된다.

내가 직접 구현하면 이 이유가 하나 더 붙는다. **며칠 쉬었다 돌아왔을 때 내가 뭘 하다 말았는지 잊어버리기 때문.** 에이전트보다 사람이 더 잘 잊는다.
