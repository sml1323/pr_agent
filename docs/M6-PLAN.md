## §0 왜 순서가 바뀌었나

원래 M6는 이랬다:

```
프롬프트 4개로 가른다  →  애그리게이터  →  데모 돌려서 눈으로 본다
```

**"눈으로 본다"가 성립하지 않는다.** 같은 diff를 12판 돌린 실측:

| | 관측 |
|---|---|
| findings 개수 | 2~4 (흔들림) |
| `sql-injection` severity | **critical 8 / high 4** |
| `sql-injection` confidence | **12판 전부 1.00** |
| 정상 diff 오탐 | `review-evasion-attempt` critical 1/3 |
| 지연 | 10.09 ~ 41.40초 |

데모를 한 번 돌려 통과하면 그건 **Pass@1** 이다. 이 프로젝트의 제1원칙("틀린 말을 안 하는 것")은
**Pass^k** 쪽이다 — 열 번 중 한 번 헛소리하면 아무도 안 믿는다.

📖 **근거**
- 책 인쇄 200 (7.2.2) — *"Pass@k = 1 − (1 − p)^k, Pass^k = p^k. p = 0.6, k = 5일 때
  Pass@5는 약 99.0%지만 Pass consecutive@5는 약 7.8%입니다."*
- 책 인쇄 201 (7.2.5) — *"Pass@k: k번 시도 중 하나 이상 성공할 확률 (…) Pass^k: k번 시도가
  모두 성공할 확률 (…) 둘을 혼동하면 에이전트를 잘못 해석하게 됩니다."*
- 우리 숫자 (p̂ = 8/12): `Pass@4 = 98.8%` vs `Pass^4 = 19.8%`

⚠️ **이 근거가 안 닿는 곳**: `p^k` 는 **p를 알 때**의 정의다. 우리는 p̂ 를 추정할 뿐이라
그대로 거듭제곱하면 위로 편향된다 — §M6-1에서 다룬다.

**그래서 새 순서:**

```
M6-0  이미 있는 데이터를 짜낸다        (비용 0 — 새 호출 없음)
      0c 픽스처 정답 선언 → 0a rationale 읽기 → 0b 보정  ← 0b 는 0c 에 의존
M6-1  자(grader)를 세운다              ← 프롬프트를 가르기 전에
M6-2  통제 실험 — 병목이 어디인가       (모델 교체)
M6-3  프롬프트를 4개로 가른다
M6-4  진짜 LLM 호출 배선 (timeout·retry)
M6-5  애그리게이터 (G6)
M6-6  demo_m6 + 완료 판정
```

⚠️ **안 닿는 곳**: 291쪽의 맥락은 *자기 진화 에이전트가 후보 업데이트를 승격시키는* 자리다.
우리 게이트와 문자 그대로 같지 않다. 다만 **재료가 같다** — 그 문단의 주어가
*"원시 웹페이지, 도구 출력과 이를 LLM이 요약한 결과는 모두 **신뢰할 수 없는 증거**"* 이고,
우리 diff가 정확히 그것이다.

**공식**: 자세한 건 [레퍼런스 §5](../learning/reference/eval-statistics.html).

```
Brier = (1/N) · Σ (confᵢ − yᵢ)²         yᵢ ∈ {0,1}   ← 구간 안 나눔
ECE   = Σ_b (n_b/N) · |acc(b) − conf(b)|             ← 구간별 가중 평균
```

⚠️ **순서 정정 (2026-08-25, 레퍼런스 쓰다가 발견)** — **M6-0b 는 M6-0c 뒤에 온다.**

`sql-injection` 이 12판 전부 `confidence=1.00` 인 걸 보고 "확신도가 상수라 보정이 깨졌다"고
쓰기 쉬운데 **그건 틀렸다:**

| finding | confidence | 맞았나 | 보정 관점 |
|---|---|---|---|
| `sql-injection` | 1.00 × 12 | ✅ 진짜 인젝션이다 | **완벽히 보정됨** |
| `review-evasion-attempt` | 1.00 | ❌ 정상 diff였다 | **여기가 미보정** |

`confidence` 의 정의는 `schema.py:52` — *"이 지적이 **사실일** 확률. 심각도와 무관하게
'내가 틀렸을 가능성'만 본다."* **severity 가 틀린 건 confidence 의 관할이 아니다.**

→ 보정은 **finding 전체 집합**에서만 잴 수 있고, 각 finding에 **맞았다/틀렸다 라벨**이 필요하다.
라벨은 `expected.yaml`(M6-0c)에서 나온다. **`y_i` 가 없으면 Brier도 ECE도 계산이 안 된다.**

**산출물**: G10(M8 범위) 결정표에 올릴 **D5 — `confidence ≥ 0.6 → 자동 게시`를 유지할 것인가.**
지금 결정하지 않는다. 근거만 만든다.

### 공식 넷 — 여기서 처음 코드가 된다

자세한 유도와 면접용 설명은 [레퍼런스](../learning/reference/eval-statistics.html).
여기엔 **무엇을 왜 쓰는지**만.

#### ① Wilson score interval — 비율의 신뢰구간

```
        p̂ + z²/2n  ±  z·√( p̂(1−p̂)/n + z²/4n² )
CI  =  ─────────────────────────────────────────
                    1 + z²/n
```

**책이 주는 Wald(`p̂ ± 2·√(p̂(1−p̂)/n)`)를 쓰지 않는다.** 우리 숫자에서 즉시 붕괴한다:

| 우리 측정 | Wald | Wilson |
|---|---|---|
| 탐지 12/12 | **[1.000, 1.000] 폭 0** | [0.757, 1.000] |
| 오탐 0/3 | **[0.000, 0.000] 폭 0** | [0.000, 0.562] |
| severity 8/12 | [0.395, 0.939] | [0.391, 0.862] |

**D4가 여기 걸린다** — Wald면 `no_tag_rule` 0/3이 "오탐 완전 해결"로 읽히고,
Wilson이면 "아직 아무것도 말할 수 없음"이다. **정반대 결정.**

📖 인쇄 221 (7.7) 의 Wald 공식은 **책 예시(n=100, p=0.7)에서는 잘 돈다.**
우리 n이 작고 p̂가 경계(0 또는 1)에 붙어서 깨지는 것 — 책이 틀린 게 아니라 **적용 범위 밖**이다.

#### ② pass^k 불편추정량

```
책:      p̂^k                    ← 쓰지 않는다
쓸 것:   C(c, k) / C(n, k)       c = 성공 판 수, n = 전체 판 수
```

`x ↦ x^k` 가 볼록이라 젠센 부등식으로 `E[p̂^k] ≥ p^k` — **거듭제곱하면 신뢰성을 과대평가한다.**
우리 (c=8, n=12) 해석적 확인:

| k | `p̂^k` | `C(c,k)/C(n,k)` | 과대 |
|---|---|---|---|
| 3 | 0.2963 | **0.2545** | 1.16배 |
| 5 | 0.1317 | 0.0707 | 1.86배 |
| 8 | 0.0390 | 0.0020 | **19.3배** |

`E[p̂³] = 0.3328` vs 참값 `0.2963` (편향 +0.037) · 불편추정량 편향 = **0.000000**

⚠️ **반대 방향 함정**: 여러 픽스처를 합칠 때 집계 p̄ 를 거듭제곱하면 이번엔 **과소**다.
→ **픽스처별로 먼저 계산하고 평균을 낸다. 그 반대가 아니다.**

#### ③ McNemar 대응 검정 — 두 프롬프트 비교

같은 픽스처·같은 시드에서 A와 B를 짝지어 돌리고, **불일치한 쌍만** 센다.

📖 인쇄 222 — *"작업별로 승패를 비교하고 두 설정이 불일치하는 사례(하나는 정답, 하나는 오답)만
살펴본 뒤 McNemar 검정 같은 방법으로 유의성을 판단합니다. 대응 분석은 작업 난이도에서 오는
공통 잠음을 빼므로 같은 표본 크기에서도 독립된 두 성공률의 차이를 보는 것보다 훨씬 민감합니다."*

**검정 가능성 사전 검사** — 불일치 쌍이 적으면 어떤 결과가 나와도 유의가 안 나온다:

```
불일치쌍 n_d = 3 → 최소 양측 p = 0.250
             5 →              0.062
             6 →              0.031   ← 여기부터 α=0.05 를 넘길 수 있다
```

**n_d < 6 이면 검정을 돌리지 마라.** 돌려도 답이 정해져 있다.

⚠️ 앞서 쓴 `차이/SE = 0.87` (√2 근사)에 대해 책이 직접 단서를 단다 —
인쇄 222: *"앞의 √2 추정은 **명백히 부족한 차이를 빠르게 거르기 위한 보수적인 기준일 뿐**입니다."*
→ **"차이 없음"의 증거로 쓰면 안 된다.** 거름망으로만.

#### ④ 다중 비교

```
가설 m개를 동시에 보면, 아무 개선이 없어도
최소 1건이 유의해 보일 확률 = 1 − (1−α)^m
```

우리 설계(프롬프트 3 × 픽스처 3 × 축 3 = **27개**): `1 − 0.95²⁷ = 0.750`

📖 인쇄 222 — *"대응책은 가설 수에 따라 유의성 임계값을 강화하는 Bonferroni식 보정**이나,
긍정적인 결과를 독립적인 확인 실행에서 재현할 때만 채택하는 것**입니다."*

**대응책이 둘이고 값이 다르다:**

| | 비용 | 우리에게 |
|---|---|---|
| Bonferroni | α = 0.05/27 = **0.0019** → 필요 K가 폭증 | 비싸다 |
| **독립 재현** | 이긴 것 **하나만** 다시 돌린다 | **훨씬 싸다** ✅ |

  얼마나 움직이는지 관찰합니다. **더 강한 모델로도 점수가 오르지 않으면 병목은 하네스입니다.**"*

⚠️ **안 닿는 곳**: 책의 부속 실험은 **OpenRouter 같은 중립 엔드포인트**에서 서로 다른 계열
