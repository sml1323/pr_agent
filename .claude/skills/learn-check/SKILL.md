# learn-check — 학습 사이클을 파일로 판정한다

## 왜 이게 있나

`CLAUDE.md` 의 학습 사이클은 네 단계다:

| | 도구 | 산출물 |
|---|---|---|
| 0-a 읽기 | `/mattpocock-skills:teach` | `learning/lessons/NNNN-*.html` |
| 0-b 만지기 | `/tycoon-sim` | `learning/sims/NNNN-*.html` |
| 0-c 적기 | **사용자가 직접** | `learning/NOTEBOOK.md` 의 해당 섹션 |
| 0-d 만들기 | 코드 | `TODO(human)` |

문제는 **건너뛰기가 쉽다**는 것이다. 특히 0-c. 읽고 굴려보면 다 안 것 같아서
적기를 생략하게 되는데, 읽기·만지기는 *알아본* 것이고 적기만이 *꺼낸* 것이다.

그리고 "했나?" 를 기억으로 답하면 틀린다. 그래서 이 스킬은 판단을 안 한다 —
**스크립트가 파일을 보고 판정한다.**

## 실행

```bash
python3 .claude/skills/learn-check/scripts/check.py
```

인자:
- 없음 → 전체 레슨 상태 표
- `3` 또는 `0003` → 그 레슨만 자세히 (어느 칸이 비었는지까지)
- `--json` → 기계용
- `--check-only` → `NOTEBOOK.md` 링크 줄을 갱신하지 않는다

기본 실행은 `NOTEBOOK.md` 각 레슨 섹션의 **산출물 링크 줄 하나**(`> 📄 ... · 🎮 ...`)를
최신 상태로 맞춘다. 그 줄 말고는 아무것도 건드리지 않는다.

종료 코드: 전부 완료면 `0`, 하나라도 빠졌으면 `1`.

## 결과를 어떻게 쓰나

표를 그대로 사용자에게 보여준 뒤, **가장 앞선 빈칸 하나만** 짚어서 다음 행동을 안내한다.
여러 개를 한꺼번에 나열하면 다시 막힌다 — 이 프로젝트는 한 번에 하나씩 간다.

| 빠진 것 | 안내 |
|---|---|
| 읽기 | 사용자가 **직접** `/mattpocock-skills:teach <주제>` 를 쳐야 한다고 안내 |
| 만지기 | `/tycoon-sim` 을 제안. 이건 Claude 가 호출할 수 있다 |
| 적기 | `learning/NOTEBOOK.md` 의 해당 섹션을 열어주고, **사용자가 쓰게 한다** |

### 절대 하지 말 것 두 가지

**1. `/mattpocock-skills:teach` 를 Claude 가 호출하려 들지 말 것.**
이 스킬은 Claude 의 스킬 목록에 뜨지 않는다. 사용자가 슬래시로 직접 쳐야만 로드된다.
그러니 "제가 실행할게요" 가 아니라 **"이 명령을 치세요"** 라고 안내한다.

**2. `NOTEBOOK.md` 의 **앞 세 칸**을 Claude 가 채우지 말 것.**
`한 문장으로` / `내 말로` / `시뮬에서 틀린 예측` — 사용자가 자기 말로 꺼내는 것이
이 단계의 전부다. 대신 채워주면 단계가 통째로 무의미해진다.
사용자가 "그냥 네가 써줘" 라고 해도, 먼저 한 문장만이라도 직접 쓰게 권한다 —
그다음 그것을 **검토**하는 게 Claude 의 몫이다.

예외: **네 번째 칸 `우리 코드 어디에 있나` 는 Claude 가 채운다** (2026-08-14 사용자 요청).
파일 경로와 행 번호를 직접 찾아서 적는다 — 판단이 아니라 사실 조회이기 때문이다.
`grep -n` 으로 실제 위치를 확인하고 적을 것. 기억으로 행 번호를 쓰지 말 것.

사용자가 쓴 뒤에는 검토한다: 틀린 이해를 잡아주고, 빠진 자리를 짚고,
맞는 부분은 더 정확한 표현을 제안한다. 칭찬은 생략한다.

## 언제 돌리나

- **세션 시작 / 오랜만에 돌아왔을 때** — 어디까지 왔는지가 첫 질문이다
- **코드 작업(0-d)에 들어가기 직전** — 앞 단계가 비어 있으면 `TODO(human)` 이
  판단이 아니라 찍기가 된다
- **레슨이나 시뮬을 새로 만든 직후** — 링크 줄을 갱신해두면 다음 세션이 빨라진다

## 검사 규칙 (스크립트가 실제로 보는 것)

- **읽기**: `learning/lessons/` 에 `NNNN-` 로 시작하는 `.html` 이 있나
- **만지기**: `learning/sims/` 에 같은 번호로 시작하는 `.html` 이 있나
- **적기**: `NOTEBOOK.md` 의 `## Lesson NN` 섹션에서 네 칸
  (`한 문장으로` / `내 말로 (3줄 이내)` / `시뮬에서 틀린 예측 / 놀란 것` / `우리 코드 어디에 있나`)
  각각 라벨 뒤에 공백 아닌 글자가 있나

칸 라벨을 바꾸려면 `scripts/check.py` 의 `FIELDS` 를 같이 고쳐야 한다.
`NOTEBOOK.md` 템플릿과 스크립트가 어긋나면 전부 미완료로 잡힌다.
