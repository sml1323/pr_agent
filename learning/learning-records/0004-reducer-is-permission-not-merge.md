# 리듀서는 합치는 법이 아니라 허가다 — 그리고 "한 번 돌아간 것"은 근거가 아니다

M5-2 `state.py` 를 앞두고 LangGraph 의 state/리듀서를 배웠다. 배운 것 자체보다 **어떻게 갈렸는지**가 남는다.

리듀서를 "여러 값을 합치는 방법"으로 이해하면 절반이다. 나머지 절반이 실제로 코드를 바꾼다 — 리듀서가 있다는 건 **"이 채널에 한 superstep 안에서 값이 여럿 와도 된다"는 허가**다. 허가가 없으면 합치는 방법 이전에 애초에 못 쓴다(`InvalidUpdateError`). 그래서 **리듀서를 안 다는 것도 능동적인 결정**이다 — 아무도 안 쓰는 `diff` 같은 키에 리듀서를 달면, 누군가 실수로 두 번 쓸 때 터지는 대신 값이 두 배가 된 채 조용히 흘러간다. 방어를 스스로 해제하는 것.

**Evidence**: 같은 노드 둘, 같은 키, 같은 state 정의로 **배선만** 바꿔 돌렸다. 순차(`START→a→b`)는 `{'box': ['B']}` 로 덮어썼고, 병렬(`START→a,b`)은 `InvalidUpdateError: Can receive only one value per step` 으로 터졌다. 문서의 *"updates to that key should override it"* 은 **"나중"이 정의되는 순차에서만** 성립한다. 같은 superstep 에는 나중이 없으므로 LangGraph 는 조용히 고르는 대신 거부한다.

**갈라놓은 것 — 1차 출처 두 문장의 모순**: `RESOURCES.md` 에 이미 적혀 있던 두 인용이 반대처럼 보였다 — *"none of the updates are applied to the state"* vs *"successful nodes... don't repeat when resumed"*. 문서를 더 읽어서는 안 갈렸다. 돌려보고 **저장소를 층별로** 들여다봐서 갈렸다: 채널(`channel_values`)에는 `[]` 가 커밋되고, 이미 끝난 노드의 출력만 `pending_writes` 로 따로 남는다. 둘 다 맞고 층이 다르다.

**메타 교훈 — 이게 이 기록의 진짜 값어치**: 이 정정을 **한 번 돌려보고 썼다가 다시 고쳤다.** 첫 실행에서는 성공 노드 둘이 다 남아서 "성공분은 보존된다"로 결론지었는데, 두 번째 실행에서는 하나만 남았다. 같은 코드다. 살아남는 건 "터진 순간까지 **끝나 있던**" 노드뿐이고 그건 스케줄링 타이밍에 달렸다 — **비결정적**이다. `docs/WORKFLOW.md` 의 "말이 아니라 출력이 근거다" 는 맞지만 불충분하다. **한 번의 출력은 근거가 아니다.** 특히 동시성이 걸린 자리에서는.

**Implications**:
- **`state.py` 의 필드마다 "몇 개 노드가 이 칸에 쓰나"를 센다.** 둘 이상 → 리듀서, 하나거나 없음 → 안 단다. 이게 M5-2 `TODO(human)` 의 판단 기준 전부다.
- **예외를 노드 밖으로 내보내지 않는다.** 내보내면 무엇이 살아남을지가 비결정적이다. 안에서 `try/except` 로 값으로 바꾸면 superstep 이 정상 종료해 넷의 결과가 **전부** 커밋된다 — 실패했다는 사실까지 값으로. [[0003-hmac-is-a-seal-not-a-lock]] 의 "방어를 넓게 바르지 말고 무엇을 막는지 짚어라" 와 같은 모양: 프레임워크의 부분 보존에 기대는 대신, 결정적인 경로 하나를 고른다.
- **M5-6 체크포인터가 선택 사항이 아님이 확정됐다.** `resume()` 이 이미 끝난 에이전트를 다시 안 부르는 것 = INV-2 가 지켜지는 자리인데, 그 메커니즘(per-task writes)이 **체크포인터 없이는 존재하지 않는다**. 인메모리로는 완료 판정 ②(`kill -9` 재개)를 못 넘는다.
- **동시성이 있는 실측은 최소 두 번 돌린다.** 앞으로 M5 데모(`demo_m5.py`)의 완료 판정에도 적용한다 — 한 번 통과한 병렬 테스트는 통과한 게 아니다.
