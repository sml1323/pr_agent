# 스키마 제약과 정책 상수는 다른 층위다

`Finding.confidence`를 처음 `Field(ge=0.6)`으로 썼다. M8 게이트의 임계값 0.6을 스키마 제약으로 착각한 것이다. 직접 돌려보고 — `confidence=0.3`짜리 finding이 `ValidationError`로 거부되는 걸 보고 — 게이트의 `else`(사람 큐) 분기가 통째로 죽는다는 걸 확인했다.

**Evidence**: 교정 후 `ge=0.0, le=1.0`으로 고쳤고, 0.3은 통과 / 1.5는 거부되는 걸 확인했다. 다만 description에 "0.6 이하면 사람 판단"이라고 쓰면서 정책이 다시 샜고, 그건 두 번째 지적 후에 고쳤다 — **같은 오해가 다른 표면으로 재발한다**는 신호다.

**Implications**:
- 앞으로 상수가 등장할 때마다 "이건 존재 가능한 값의 범위인가, 그중 뭘 통과시킬지의 정책인가"를 먼저 묻게 해야 한다. M8 게이트를 직접 만들 때 다시 시험대에 오른다.
- 관련 개념(스키마가 형식은 강제하지만 내용은 강제하지 않는다)은 [Lesson 01](../lessons/0001-schema-not-prompt.html)에서 다뤘다. 이건 G1(rationale 사후 검증)과 M8 게이트의 존재 이유로 이어진다.
- LLM API 자체는 아직 미경험. `parse()` 호출을 직접 해본 적 없음 — 다음 레슨의 출발점.
