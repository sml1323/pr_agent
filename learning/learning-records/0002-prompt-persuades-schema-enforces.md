# 프롬프트는 설득이고 스키마는 강제다 — 양방향으로 확인함

M0에서 프롬프트 지시가 **안 먹히는 경우와 넘겨짚는 경우를 둘 다** 관측했다. `severity=critical로 지정하라`고 써도 모델이 `medium/docs`로 분류했고(안 먹힘), 반대로 회피 시도 패턴 4개만 예시로 줬는데 목록에 없는 감정 호소까지 잡아냈다(과잉 일반화). 같은 프롬프트에 출력이 매번 달랐다.

**Evidence**: 사용자가 엣지 케이스로 "감정에 호소하는 주석"을 스스로 제시했고, 그 가설을 `fixtures/sample_emotional.diff`로 직접 검증했다. 예측은 "목록에 없으니 안 걸린다"였고 결과는 반대였다 — **스키마의 사고방식(`Literal`은 목록에 없으면 진짜로 거부)을 프롬프트에 적용한 오류**였다. 이 구분은 이제 이해했다고 본다.

**Implications**:
- 앞으로 "프롬프트에 썼으니 된다"를 근거로 쓰지 않게 해야 한다. 강제가 필요하면 스키마·코드로 내린다.
- 프롬프트 강조가 **제로섬**이라는 것도 같이 관측했다(인젝션 규칙 강화 → 4분류 검토가 밀려 finding 4→1개). M6에서 에이전트를 넷으로 쪼개는 이유의 실측 근거이므로, M6 브리핑에서 이 데이터를 다시 꺼낼 것.
- 이해도 3문 중 **1번(severity/confidence 분리 근거)과 3번(변경 영향)은 답하지 못했다.** 게이트가 아직 코드로 존재하지 않아 상상으로 답해야 하는 상태였다. **M8 완료 후 3번을 다시 물을 것** — 그때가 진짜 측정 시점이다.
