# 학습 노트 — 내가 정리한 핵심

> 읽기(레슨)와 만지기(시뮬 · 노트북 · 트레이스)를 끝낸 뒤 **내 말로** 적는 곳. Claude가 채우지 않는다.
> 규칙 하나: **레슨을 다시 보지 말고 먼저 쓴다.** 못 쓰겠으면 그게 아직 안 배운 부분이다.
> 다 쓰면 Claude가 검토한다 — 틀린 곳을 잡아주고, 빠진 자리를 짚어준다.

**왜 쓰나**: 읽으면 "아 맞다" 하고 넘어간다(유창성 착각). 쓰면 뭘 모르는지가 드러난다.
그리고 몇 주 뒤 돌아왔을 때 **레슨 5개를 다시 읽는 것보다 이 파일 한 장을 읽는 게 빠르다.**

**형식**: 앞 **세 칸을 사람이** 채운다. 길게 쓰지 않는다 — 짧을수록 다시 읽는다.
세 번째 칸의 이름은 **만지기 도구에 따라 바뀐다** (2026-08-27) — 시뮬이면 "틀린 예측",
노트북이면 "직접 구현하며 틀린 것", 트레이스면 "실행이 예상과 달랐던 곳". 묻는 건 같다:
**어디서 틀렸나.** 맞은 건 나중에 복원되지만 틀렸다 고친 건 안 적으면 사라진다.
네 번째 **"우리 코드 어디에 있나"** 는 Claude 가 파일·행 번호를 찾아 적는다 (2026-08-14부터).
그건 판단이 아니라 사실 조회라서 — 사람이 꺼내야 하는 건 앞 세 칸이다.

## Lesson 01 — JSON을 부탁하지 말고 스키마로 강제하라

> 📄 [레슨](lessons/0001-schema-not-prompt.html) · 🎮 [시뮬](sims/0001-schema-gate.html)

**한 문장으로**: pydantic 모델을 `response_format` 으로 넘기면 토큰 디코딩 단계에서 형태가 강제된다.

**내 말로 (3줄 이내)**: `completions.parse` 함수의 `response_format` 에 pydantic 모델을 정의하여
넘기면, 토큰 디코딩 단계에서 모델 스키마 형태를 강제하여 원하는 형태의 결과를 얻을 수 있다.
`choices[0].message.parsed` 형태로 output 사용.

**시뮬에서 틀린 예측 / 놀란 것**: 없음.

필드는 agent_type, severity, category, file, line, confidence, rationale.
`str`·`float`·`ge`·`le` 가 값을 강제하고, `description` 은 모델에게 부탁하는 형태.
`ReviewResult` 는 최상위 객체 — 지적이 여러 개이고, structured output 은 최상위가 배열이면 거부한다.

> **빠진 것**: "무엇이 강제되나" 는 맞는데 **"무엇이 강제 안 되나"** 가 없다.

>

## Lesson 02 — PR diff는 공격자가 쓴 글이다

> 📄 [레슨](lessons/0002-untrusted-diff.html) · 🎮 [시뮬](sims/0002-injection-lab.html)

**한 문장으로**: 프롬프트 인젝션은 근본적으로 해결책이 없다. 방어는 확률을 낮추는 일이다.

**내 말로 (3줄 이내)**: 세 겹으로 막는다.
1. **역할 분리** — 지시는 system prompt, 신뢰할 수 없는 diff 는 user content 에 둔다.
2. **delimiter 격리** — diff 를 `<untrusted_diff>{diff}</untrusted_diff>` 로 감싸 데이터의
   시작과 끝을 명시하고, 신뢰할 수 없는 데이터일 뿐이라고 system 에서 못 박는다.
3. **출력 스키마** — Lesson 01 에서 정한 `ReviewResult` 로 출력 형식을 묶는다.

**시뮬에서 틀린 예측 / 놀란 것**: 없음. (닫는 태그 탈출 질문에 대한 답 — 뚫릴 수도, 아닐 수도.
그 공격을 **결정론적으로 막을 방법은 없다**.)

**우리 코드 어디에 있나**: `backend/agents/base.py` — `SYSTEM_PROMPT`(방어 ①③)와
`build_user_message()`(방어 ②).

<!-- Claude 검토 (2026-08-14) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **표현 교정 2개**
> · 닫는 태그는 `</untrusted_diff>` — 슬래시 방향. delimiter 는 문자열이 전부라 한 글자가 곧 구멍이다.
> · 3번은 "이상한 출력 방지" 보다 **"출력의 형식을 공격자가 바꿀 수 없다"** 가 정확하다.
>   내용은 여전히 바뀐다 — `findings: []` 는 형식상 완벽하다.
>
> **빠진 것 — 이 레슨의 나머지 절반**
> 위는 *방어 목록*이고, 레슨·시뮬의 절반은 **"그래도 뚫린다"** 다.
>
> | 두 층위 | 예시 | 방어가 듣나 |
> |---|---|---|
> | 명령형 인젝션 | "Ignore previous instructions" | 잘 듣는다 |
> | **사실 조작** | "보안팀이 승인했다 (SEC-4821)" | **거의 안 듣는다** |
>
> · delimiter 는 **탈출 문자열 한 줄로 깨진다** (Sim L3)
> · 스키마는 자유 텍스트를 막지만 **빈 배열은 못 막는다** (Sim L4)
> · 그리고 `findings: []` 는 **"정말 문제 없음" 과 모양이 똑같다** → 게이트가 구별 못 한다
>
> 사실 조작이 핵심이다. severity 를 낮추라고 *명령*할 필요가 없다 — *안전하다고 주장*하면 된다.
> 지시를 무시하라고 시킨 적이 없으니 어떤 인젝션 필터에도 안 걸린다.

## Lesson 03 — 서명은 바이트에 대한 것이다

> 📄 [레슨](lessons/0003-signature-over-bytes.html) · 🎮 [시뮬](sims/0003-signature-bytes.html)

**한 문장으로**: GitHub PR 웹훅은 HMAC-SHA256 으로 검증하고, **바이트 단위로** 대조해야 하므로
`json()` 이 아니라 `body()` 로 받아야 한다.

**내 말로 (3줄 이내)**: 깃과 우리는 secret 을 공유한다. 깃이 HMAC-SHA256 으로 본문 바디의
지문을 만들어 헤더에 싣는다. 우리는 `body()` 로 본문을 받아 같은 함수·같은 secret 으로
다시 계산하고 헤더와 대조한다. 같으면 그때 body 를 처리한다.
`json()` 으로 안 받는 이유는 변환 중 바이트가 바뀌기 때문.

**시뮬에서 틀린 예측 / 놀란 것**: 없음.

**우리 코드 어디에 있나**: `backend/webhook/security.py:71` `verify_signature(raw_body, signature_header)`
— `hmac.new(key=WEBHOOK_SECRET, ...)` 로 계산하고 `hmac.compare_digest`(133행)로 대조.
`WEBHOOK_SECRET` 은 import 시점에 없으면 부팅을 거부한다(62~68행).
raw body 를 읽는 자리는 `backend/webhook/app.py:63` `body = await request.body()` — **파싱보다 먼저**.

<!-- Claude 검토 (2026-08-14) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **어휘 교정 — 이 레슨의 핵심이다**
> "암호화" 가 아니다. 두 개는 다른 물건이다:
>
> | | 방향 | 내용 | 목적 |
> |---|---|---|---|
> | 암호화 | 왕복 (복호화 가능) | **숨긴다** | 비밀 유지 |
> | HMAC | 편도 | **평문 그대로 간다** | 변조 탐지 |
>
> 헤더에 실리는 것은 본문이 아니라 **본문의 지문**이다. body 는 평문으로 가고 누구나 읽는다.
> 시뮬 L4 에서 secret 만 가려지고 body 는 그대로 보였던 게 그 뜻이다.
>
> 이 구분이 중요한 이유는 **다음 생각을 차단하기 때문**이다 —
> "암호화됐으니 body 는 안전하다" 로 이어진다. 서명 통과가 증명하는 건 **출처**뿐이고,
> body 안의 diff 는 여전히 공격자가 쓴 글이다. 그건 [Lesson 02] 가 따로 막는다.
> **두 경계가 막는 것이 다르다.**
> 관련: `learning-records/0003-hmac-is-a-seal-not-a-lock.md` (같은 자리를 이미 한 번 겪었다)
>
> **빠진 것 2개**
> · **타이밍 안전 비교** — `==` 가 아니라 `hmac.compare_digest`. `==` 는 첫 불일치에서 멈춰서
>   "몇 글자까지 맞았나" 를 시간으로 흘린다 (Sim L5). 우리 코드 `security.py:133`.
> · **응답 코드** — 우리는 400, GitHub 공식 예제는 403. 의도된 차이이고 INV-1 에 적혀 있다.

## Lesson 04 — 같은 배달이 두 번 왔을 때

> 📄 [레슨](lessons/0004-same-delivery-twice.html) · 🎮 [시뮬](sims/0004-idempotency-timeline.html)

**한 문장으로**: 웹훅 중복은 delivery ID 를 set 에 넣어보고 **크기 변화**로 판정한다.

**내 말로 (3줄 이내)**: 먼저 set 의 길이를 재서 `before` 에 저장한다. 그 set 에 delivery ID 를
`add` 해본다 — set 자료구조라 중복이면 크기가 증가하지 않는다.
`add` 후 길이와 `before` 를 비교해 동일하면 중복, 아니면 통과.

**시뮬에서 틀린 예측 / 놀란 것**: 없음.

**우리 코드 어디에 있나**: `backend/queue/router.py:51` `is_duplicate(delivery_id)` —
`before = len(_seen_deliveries)` → `.add()` → `return len(...) == before` (67~69행).
자료구조가 **둘**이다: `_queue`(list, 20행)는 처리할 잡, `_seen_deliveries`(set, 26행)는 본 ID 기억.
호출부는 `backend/webhook/app.py:109` — `is_duplicate()` 통과한 것만 `enqueue()`(112행).

<!-- Claude 검토 (2026-08-14) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **이름 교정** — 처음에 "큐를 set 으로 관리" 라고 했는데 둘은 별개다.
> `len()` 비교는 **`_seen_deliveries`(set)** 에서 일어나고, 큐(list)는 판정을 통과한 뒤 `append` 될 뿐이다.
>
> | | 무엇을 세나 | 줄어드나 |
> |---|---|---|
> | `len(_queue)` | 아직 처리 안 된 잡 | 워커가 꺼내면 줄어든다 |
> | `len(_seen_deliveries)` | 지금까지 본 배달 | **절대 안 줄어든다** ← 함정 ② |
>
> **왜 `add` 의 반환값을 안 쓰나**: `set.add()` 는 아무것도 돌려주지 않는다.
> 그래서 전후 `len()` 비교가 관용구가 된다. 핵심은 **확인과 기록이 한 동작**이라는 것 —
> `if x in seen` 과 `seen.add(x)` 를 따로 하면 그 사이에 틈이 생긴다 (Sim L2, 340ms 경계).
>
> **아직 안 적힌 두 함정**
> · **재시작을 못 넘는다** — `_seen_deliveries` 는 프로세스 메모리다. 껐다 켜면 통째로 사라진다.
>   버그가 아니라 **알고 미룬 타협**이고, M4 에서 Redis TTL 로 간다 (Sim L4).
> · **10초의 벽** — GitHub 은 실패한 배달을 **자동 재시도하지 않는다**. 10초를 넘기면 이벤트가
>   **영구 유실**된다. 그래서 큐는 "느려도 되게" 가 아니라 **"유실을 막으려고"** 있다 (Sim L5).

## Lesson 05 — 삭제로 가는 문은 네 개다

> 📄 [레슨](lessons/0005-four-doors-to-delete.html) · 🎮 [시뮬](sims/0005-four-doors.html)

**한 문장으로**: 감사 로그를 변경·삭제하지 못하게 하려면 **막아야 할 문이 여러 개**고,
문마다 자물쇠가 다르다.

**내 말로 (3줄 이내)**: 기본적으로 `UPDATE`·`DELETE` 에 트리거를 걸어 행 단위 변경·삭제를 막는다.
`TRUNCATE` 는 행 단위 연산이 아니라 별도의 TRUNCATE 트리거를 건다.
추가로 `drop` 은 또 다른 연산이라 트리거로 못 막고 RBAC 으로 제한한다.

**시뮬에서 틀린 예측 / 놀란 것**: 없음.

**우리 코드 어디에 있나**: `migrations/003_immutable.sql` — 거부 함수
`agent_events_append_only()`(23행)를 트리거 셋이 공유한다. UPDATE(38행) · DELETE(53행) ·
TRUNCATE(65행) **셋 다 완성**(2026-08-14). 문 ④⑤(`drop_chunks`·`DROP TABLE`)는
`006_rbac.sql` 의 일이고 **아직 없다 — 지금 `postgres` 슈퍼유저라 그냥 통과한다**.

<!-- Claude 검토 (2026-08-14) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **미묘한 교정 — "DDL 이라서 못 막는다" 가 아니다**
> `TRUNCATE` 도 넓게는 DDL 인데 막을 수 있다. 진짜 기준은 **그 사건을 잡는 트리거가 존재하냐** 다.
>
> | 명령 | 대응 트리거 | 막히나 |
> |---|---|---|
> | UPDATE / DELETE | `BEFORE UPDATE/DELETE ... FOR EACH ROW` | ✅ |
> | TRUNCATE | `BEFORE TRUNCATE ... FOR EACH STATEMENT` | ✅ |
> | `drop_chunks()` / `DROP TABLE` | **없음** | ❌ 권한으로만 |
>
> Postgres 가 트리거를 걸 수 있는 사건은 INSERT/UPDATE/DELETE/TRUNCATE **넷뿐**이다.
> 테이블을 DROP 하는 건 그 목록에 없다. 그래서 남은 방어가 권한뿐이다.
>
> 그리고 `TRUNCATE` 가 별도 트리거를 요구하는 진짜 이유는 문서 문장이다 —
> *"TRUNCATE will not fire any ON DELETE triggers."* 행 단위가 아니라서가 아니라,
> **아예 다른 트리거 종류를 발동시키기 때문**이다. 그래서 `FOR EACH ROW` 로는 쓸 수조차 없다.
>
> **아직 안 적힌 것 — 왜 두 겹인가**
> 시뮬에서 접속 주체를 「소유자」로 바꾸면 **RBAC 이 통째로 무효**가 된다. 롤 제한은 앱 롤에게만 걸린다.
> 두 층이 막는 대상이 다르다:
> · **트리거** — "그 동작을 허용하지 않는다" (누가 접속하든)
> · **롤** — "그럴 자격이 없다" (앱 자격증명이 유출돼도 감사 로그는 남는다)
>
> ⚠️ 지금 우리 `.env` 의 `DATABASE_URL` 은 `postgres` 슈퍼유저다 — **소유자 상태**다.
>
> **프레임 한 줄**: "방법이 여러 가지" 보다 **"막아야 할 문이 여러 개"**. 방법을 고르는 게 아니라
> 문마다 다른 자물쇠가 필요하고, 하나라도 안 잠그면 나머지를 아무리 잘 잠가도 소용없다.

## Lesson 06 — "아무 문제 없음"과 "아무도 안 봄"

> 📄 [레슨](lessons/0006-nobody-looked.html) · 🎮 [시뮬](sims/0006-partial-failure.html)

**한 문장으로**: 결함을 못 찾은 경우와, 에러나 타임아웃으로 인해 애초에 돌지 않은 경우를
구분해야 한다.

**내 말로 (3줄 이내)**: 실패나 타임아웃으로 인해서 정상적으로 에이전트가 돌지 않았을 경우
`failed` 리스트에 이름을 추가해주는 것으로 해결할 수 있다.
`gather` 의 기본 / 파라미터 / `TaskGroup` / superstep 이거는 헷갈리네.

**시뮬에서 틀린 예측 / 놀란 것**: 없음.

**우리 코드 어디에 있나**: **아직 없다 — M5 에서 만든다** (`backend/orchestration/engine.py` +

<!-- Claude 검토 (2026-08-18) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **한 문장은 정확하다.** 두 경우를 "구분해야 한다"가 이 레슨의 전부다.

>
> | 층 | 무엇 | 하나가 터지면 나머지를 |
> |---|---|---|
> | asyncio | `gather()` 기본 | **내버려둔다** — 안 죽고 계속 돌며 토큰을 태운다 (고아) |

> | asyncio | `TaskGroup` | **죽인다** — 취소하고 `ExceptionGroup` |
> | LangGraph | superstep | 위 셋과 **다른 층**. ~~예외가 나가면 성공한 결과까지 롤백~~ → **정정, 아래** |
>
> 앞 셋은 *"나머지를 어떻게 하나"* 라는 **한 질문에 대한 세 답**이다 — 방치 / 수집 / 취소.

>
> **그런데 외울 필요가 없다.** 노드 안에서 `try/except` 로 실패를 **값**으로 바꾸면
> 예외가 애초에 밖으로 안 나가고, 그러면 **넷의 차이가 거의 사라진다**
> (시뮬 샌드박스에서 커버리지 동봉을 켜고 팬인 방식을 바꿔보면 결과가 안 변한다).
> M5 에서 실제로 쓸 건 **하나** — 노드 안 try/except + LangGraph.
> 나머지 셋은 "왜 그렇게 해야 하는지"의 근거로만 필요하다. **안 쓰기로 한 선택지**다.
>
> **3줄에서 빠진 것**: `failed` 명단을 넣는 것까지는 맞는데, **그게 왜 듣는지**가 없다.
> findings 는 L3 와 L4 가 똑같이 `[]` 였다. 바뀐 건 옆에 붙은 명단 하나뿐이고
> 그것만으로 자동 게시 → 사람 큐로 뒤집혔다. **판정을 바꾼 건 findings 가 아니라 커버리지다.**

> |---|---|---|
> | 채널 (정식 체크포인트) | `channel_values: []` | *"none of the updates are applied to the state"* |

> **더 중요한 것**: 같은 코드를 두 번 돌렸는데 결과가 달랐다. 한 번은 둘 다 남고

> 그건 타이밍에 달렸다 — **비결정적**이다. (두 번째 실행에선 `a` 가 write 를 저장하려는

>

> 안에서 잡으면 superstep 이 정상 종료해 넷의 결과가 전부 커밋된다(실패 사실까지 값으로).
>
> 그리고 이게 `resume()` 이 성립하는 근거이자 INV-2 가 지켜지는 자리다 — **체크포인터가 있을 때만**.

## Lesson 07 — 리듀서는 합치는 법이 아니라 허가다

> 📄 [레슨](lessons/0007-permission-to-write-together.html) · 🎮 [시뮬](sims/0007-superstep-lab.html)

**한 문장으로**: 리듀서를 통해 한 채널을 여러 노드가 편집할 수 있도록 할 수 있다.

**내 말로 (3줄 이내)**: 리듀서는 한 채널에 여러 노드가 쓸 수 있게 **허가**해주는 것.

**어떻게 합칠지**(`operator.add` = 이어붙이기)도 같이 정의해준다.
superstep 은 단계 — 노드들의 층.

**시뮬에서 틀린 예측 / 놀란 것**: security 만 터졌을 때 나머지는 정상 작동할 줄 알았는데
**전체가 터졌다.**

**우리 코드 어디에 있나**: `backend/orchestration/state.py` — **아직 `TODO(human)`(45행)**.
`ReviewState`(35행)의 필드가 이 판단이다. 착지점은 이미 파여 있다:
`migrations/004_truth.sql:94` 의 `failed_agents TEXT[]` 가 Lesson 06 의 명단이 갈 곳이고,
`backend/agents/schema.py` 의 `Finding.agent_type` 이 **채널을 4개로 안 나눠도 되는 이유**다
(누가 찾았는지가 값 안에 있으므로 `findings` 한 칸이면 된다).
그리고 `engine.py:109` 의 `get_state()` 가 돌려줄 dict 가 바로 이 state 다.

<!-- Claude 검토 (2026-08-19) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **방향이 뒤집혔다 — 그게 이 레슨의 전부다.** 첫 시도는 "쓰기를 제한하는 자물쇠"였다.
> 반례 하나로 뒤집혔다: 자물쇠라면 없앨 때 자유로워져야 하는데, 없애니까 `InvalidUpdateError` 가 났다.
> 이름이 오해를 만든다 — `reduce` 계열의 "여러 값을 하나로 줄이는 함수"인데
> 한국어로는 "제한기"처럼 들린다.
>
> **"편집"은 한 단어만 아쉽다.** 노드는 state 를 편집하지 않는다 — **자기 조각만 던진다.**
> 이걸 편집으로 이해하면 이런 실수를 한다:
>
> ```python
> return {"findings": state["findings"] + [내것]}   # ❌ 리듀서가 또 더한다
> → ['앞 노드 것', '앞 노드 것', '내것']              # 중복
>
> return {"findings": [내것]}                        # ✅ 합치는 건 리듀서 몫
> → ['앞 노드 것', '내것']
> ```
>
> **빠진 것 하나**: 리듀서가 **필요 없는 채널을 비워두는 것도 결정**이라는 자리.
> `diff` 는 아무도 안 쓰니 리듀서가 필요 없는데, "필요 없으니 아무래도 상관없다"가 아니라
> **"안 단다 — 둘이 쓰는 사고가 나면 터져서 잡히게"** 다. 시뮬 프리셋 ③ 이 그 함정이었다
> (에러 없이 diff 가 3배). M6 에서 에이전트를 실제로 구현할 때 갈린다.
>
> **superstep — "노드들의 층" 이 정확하다.** 다만 층은 그림이 아니라 **실행이** 긋는다.
> 사용자의 upbit 프로젝트가 그 예다: 같은 그래프인데
> `route_by_anomaly_type` 이 반환하는 것에 따라 층 1 에 노드가 둘이 서기도, 하나만 서기도 한다.

## Lesson 08 — 엣지는 시간을 긋는다

> 📄 [레슨](lessons/0008-edges-draw-time.html) · 🎮 [시뮬](sims/0008-wire-the-graph.html)

**한 문장으로**: superstep 은 LangGraph **실행**의 한 층이고, 엣지가 그 층을 이룬다.

**내 말로 (3줄 이내)**: 엣지가 superstep 을 구성하고, conditional edge 를 통해

**시뮬에서 틀린 예측 / 놀란 것**: **④ 절반만 팬인**이 틀렸다. 아래 2개는 바로 END 로 가는데,

→ 아니었다. superstep 이 **배리어**라서 층 전체를 기다린다.

**우리 코드 어디에 있나**: `backend/orchestration/langgraph_engine.py` — **아직 `TODO(human)` 둘**
(`_build()` 130행 · `get_state()` 156행). `AGENT_TYPES`(41행)로 넷을 돌린다.
`engine.py` 의 `run()` 이 `invoke(state, config)` 를 부르는 자리가 **층이 그어지는 순간**이고,
`state.py` 의 `ReviewState` 가 그 층들이 굴리는 dict 다. 세 파일이 여기서 만난다.

<!-- Claude 검토 (2026-08-19) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **한 문장은 두 번째 시도에서 정확해졌다.** 첫 시도는 *"엣지는 하나의 superstep 이다"* 였다 —
> [Lesson 07](lessons/0007-permission-to-write-together.html) 의 *"superstep 은 node 네?"* 와
> **같은 종류의 실수**다: 범주가 다른 둘을 `=` 로 묶는 것. 엣지는 설계도에 있고
> superstep 은 실행에만 있다. `=` 가 아니라 `→` 다.
>
> **틀린 예측이 이 레슨의 진짜 소득이다.** 추론 자체는 정교했다 —
> "aggregate 와 이어지지 않은 노드가 늦으면 aggregate 가 먼저 돌 것".
> 실측으로 갈랐다 (`testing`·`docs` 를 5배 느리게):
>
> ```
> security  끝남  t=0.11초
> quality   끝남  t=0.11초
> testing   끝남  t=0.51초     ← aggregate 와 엣지로 안 이어져 있는데
> docs      끝남  t=0.51초
> aggregate 시작 t=0.51초  ← 4개 봄   (0.11초가 아니다)
> ```
>
> **superstep 은 배리어다.** 엣지는 "어느 층에 서나"를 정하지 "누구를 기다리나"를 정하지 않는다.
> 층에 서는 순간 그 층 전체와 운명을 같이 한다.
>
> 📌 **이게 M5-5(타임아웃)가 필요한 이유다.** 배리어라면 한 노드가 안 끝날 때
> 그래프 전체가 영원히 멈춘다 — 나머지 셋이 다 끝나도 소용없다.
> `03-build-plan.md` M5 완료 판정 ③("무한 대기시켜도 애그리게이터가 나머지로 진행")을
> 통과하려면 **노드 자신이 시간을 재고 스스로 끝나야** 한다. 밖에서 기다려주지 않는다.
>
> **3줄에서 한 군데** — *"conditional edge 로 **조건부 superstep** 을 만든다"*.
> superstep 이 조건부가 되는 게 아니라 **그 층에 누가 서는지가 실행 때 정해진다.**
> 사용자의 upbit 실측이 그 예다: `zscore` 면 층 1 에 노드 둘, `rsi` 면 하나.

## Lesson 09 — 예상한 실패와 우리 버그는 다르다

> 📄 [레슨](lessons/0009-expected-failure-vs-bug.html) · 🎮 [시뮬](sims/0009-catch-scope.html)

**한 문장으로**: 예외처리의 순서를 좁은 범위 → 포괄적인 범위로 써야 함.

**내 말로 (3줄 이내)**: 예외절은 좁은 것부터.
우리 버그는 종류가 많으니 `Exception` 으로.
`KeyboardInterrupt` 는 명시 안 한다.

**시뮬에서 틀린 예측 / 놀란 것**: 없음.

**우리 코드 어디에 있나**: `backend/orchestration/langgraph_engine.py` — **아직 `TODO(human)`**
(105행). `_call_agent()`(91행)이 예외를 **던지고**, `_run_specialist()`(144행)이 그걸
값으로 바꾼다. 노드 넷(152행~)이 전부 `_run_specialist` 하나를 부르므로 판단은 한 자리에만 있다.
지금은 `RuntimeError` 를 던지지만 **M6 에서 `OpenAIError` 계열로 바뀐다** — 그때 다시 열 자리.
착지점: `state.py` 의 `failed_agents`(74행)에 이름만 담고, 이유는 M3 `record_event` 의 몫.

<!-- Claude 검토 (2026-08-20) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **레슨이 압축적이어서 한 번 막혔고, "이유부터" 다시 풀어서 잡혔다.** 그 경로를 남긴다 —
> 이 레슨의 진짜 순서는 *기술 → 개념* 이 아니라 **상황 → 왜 곤란한가 → 도구** 였다:
>
> 1. 에이전트가 결과를 못 냈다. **이유가 둘**이다 — 바깥 탓(서버) / 내 탓(오타).
> 2. 둘은 **내가 할 일이 다르다** — 하나는 기다리면 되고 하나는 고쳐야 한다.
> 3. 그런데 `except Exception` 은 둘을 **같은 기록**으로 만든다 (`failed_agents=["security"]`).
> 4. 그러면 3주 뒤 "실패율 100%"를 보고 재시도·모델교체·타임아웃을 다 해봐도 안 고쳐진다.
>    원인은 오타 한 글자였으니까.
> 5. 예외에는 **이름표(타입)** 가 있고, `except` 는 이름표를 골라 잡을 수 있다.
>
> **막혔던 진짜 지점 — 질문 둘이 하나로 섞였다.**
> 첫 시도는 *"KeyError·interrupt 부터 쓰고 openai exception 을 쓴다"* 였다.
>
> | 질문 | 답 |
> |---|---|
> | ① **어떤 절을 쓸까** | **다르게 다루고 싶은 경우의 수**만큼 (우리는 2 — 바깥 탓/내 탓) |
> | ② **어떤 순서로** | 좁은 것 위, 넓은 것 아래 |
>
> ②는 처음부터 맞았다. ①에서 "좁은 것 = KeyError" 로 읽어서 그걸 절로 쓰려 했다.
> **버그는 이름을 미리 모른다** — 알면 애초에 안 냈다. 그래서 지목이 아니라 `Exception` 이 받는다.
> `KeyboardInterrupt` 는 잡으면 Ctrl+C 가 안 먹으므로 아예 안 쓴다(파이썬이 `Exception` 밖에 뒀다).
>
> 📌 **절의 개수 = 예외 종류가 아니라 "다르게 다룰 경우의 수"** 다. rate limit 만 재시도하고 싶어지면
> 셋이 된다: `RateLimitError` → `OpenAIError` → `Exception`. 여전히 좁은 것부터다.
>
> **한 문장에서 빠진 것**: 순서 규칙은 맞는데 **왜 가르는지**가 없다.
> 순서는 도구고, 목적은 *"우리 버그가 API 실패로 위장하지 않게"* 다.
> M6 에서 이 코드를 다시 열 때 필요한 건 순서보다 그 목적이다.
>
> **`failed_agents` 에는 둘 다 이름만 넣는 게 맞다** — 읽는 사람이 다르기 때문이다.
> 게이트(M8)는 "누가 커버 안 됐나"만 필요하고 이유는 안 쓴다. 이유는 로그(→M3)로 간다.

<!-- Claude 검토 (2026-08-21) — 위는 사용자가 쓴 것, 아래는 검토 의견 -->
> **결론은 맞다.** 세 층을 다 짚었고 착지점(HTTP request)도 맞다. 두 군데만 조인다.
>
> **① "정확히 정지시킬 수 있다" — 이 표현이 레슨의 제목과 정면으로 부딪힌다.**
> HTTP 타임아웃도 **저쪽을 멈추지 못한다.** 우리 쪽 소켓을 닫는 것뿐이고,
> 서버는 여전히 토큰을 만들고 있을 수 있다. 실측 ①(`cancel() → False`)이 층만 바뀌었지 그대로다.
>
> 그럼 뭐가 달라지나 — **우리가 예외를 받는다는 것.** 그게 전부이고, 그게 충분하다.
>
> | | 저쪽이 멈추나 | 우리가 예외를 받나 |
> |---|---|---|
> | 스레드 타임아웃 | ❌ | ⭕ (하지만 좀비가 남는다) |
> | HTTP 타임아웃 | ❌ | ⭕ (연결은 정리된다) |
>
> 📌 **"멈춘다"가 아니라 "포기하고 예외를 받는다"** 로 읽어야 M6 에서 재시도를 붙일 때
> INV-2 를 안 잊는다 — 저쪽이 이미 끝냈을 수 있으니까.
>
> **② "동기함수에는 거는 것이 불가능" — 반만 맞다. 여기가 세 층 중 둘을 뭉갠다.**
>
> | | 동기 노드에 | |
> |---|---|---|
> | ② 노드 **밖** (`add_node(timeout=)`) | ❌ 불가능 | compile 에서 `ValueError` |
> | ③ 노드 **안** (HTTP `timeout=`) | ⭕ **가능** | 우리가 실제로 쓸 것 |
>
> 못 거는 건 **동기 함수**가 아니라 **동기 함수를 밖에서 끊는 것**이다.
> 그 안의 HTTP 호출에는 얼마든지 건다 — 그래서 우리 노드를 `async` 로 안 바꿔도 M5-5 가 된다.
> **이 구분이 없으면 "그럼 전부 async 로 고쳐야 하나"** 라는 안 해도 될 공사로 간다.
>
> **③ 빠진 것 — 왜 하필 HTTP 냐의 진짜 이유가 두 겹인데 한 겹만 적혔다.**
>
> 적힌 것: 소켓은 실제로 닫을 수 있는 대상이다. (맞다)
> 빠진 것: **예외가 `try` 안에서 난다.** ②는 노드 밖에서 나서 `except` 를 비껴가고,
> ③은 `_call_agent()` 안에서 나므로 09 에서 만든 `except` 절 둘이 **그대로 받는다.**
>
> 09 와 10 은 같은 질문의 두 반쪽이다 — 09 는 *터진 걸 어떻게 나누나*,
> 10 은 *터지게 만들려면 어디서 재나*. 둘 다 답이 **`try` 의 위치**로 모인다.
> M5-5 가 "타임아웃 값을 정하는 일"이 아니라 **"터질 자리를 `try` 안으로 옮기는 일"** 인 이유다.

## 노트북 01 — Wilson vs Wald · `0/3` 은 오탐률 0% 가 아니다

> 📓 [노트북](notebooks/01-wilson-vs-wald.ipynb) · M6-1 의 자(ruler) 부품 ①

**한 문장으로**: 관측한 비율(p̂)은 진짜 확률(p)이 아니다 — 그래서 점이 아니라 폭으로 말한다.

**내 말로 (3줄 이내)**: 신뢰구간을 **만드는** 방법 중 Wald 와 Wilson 이 있고 Wilson 을 쓴다.
Wald 는 분모에서 p 를 p̂ 으로 근사하기 때문에, p̂ 이 양 극단이면 폭이 0 이 된다.
Wilson 은 그렇게 안 해서 커버리지가 95% 근처를 유지한다.
LLM 호출 비용·시간 때문에 우리 n 은 작을 수밖에 없어서, 그 자리에서 Wilson 이 맞다.

**직접 구현하며 틀린 것 / 놀란 것**: **층을 세 번 섞었다.**
구간 `[0.5, 0.9]` 를 "50~90% 신뢰"로 읽었는데, 실은 **"탐지율이 50~90% 사이"** 였다.
신뢰(95%)는 구간 **안**이 아니라 `z` 에 **밖**에 붙어 있다. 둘 다 0~1 숫자라 계속 섞였다.
같은 미끄러짐이 "정규에러"·"커버리지가 신뢰구간을 수식" 으로도 났다. 층은 셋이다 —
**`p`/`p̂`(무엇을 재나) · `[lo, hi]`(무엇을 만드나) · 커버리지(만든 걸 채점).**

**우리 코드 어디에 있나**: `evals/stats.py` 의 `wilson_ci` — `Z95 = 1.96` 은 정책이 아니라
측정 관례라서 여기 산다 (게이트 임계값은 M8 `backend/gate/` 까지 어디에도 안 나온다).
`n <= 0` 은 `ValueError` 로 터뜨린다 — 삼키면 `None` 이 흘러가 더 늦게, 더 이상한 메시지로 터진다.
패키지는 `backend/` **밖**에 산다 (구조 결정 카드, `docs/CURRENT.md` 「확정된 결정」).

## M6-3a ① — 캐시는 두 종류다 · 그리고 "없다"는 두 번 재야 안다

> 📖 책 2.3.3·2.3.4 (인쇄 53) · 🔬 실측 [`scratch/recon_prompt_cache.py`](../scratch/recon_prompt_cache.py)
