# 작업 노트

## 학습자에 대해

- 파이썬은 안다. **LLM API는 처음.** 첫 `parse()` 호출을 아직 안 해봤다
- 백지에서 시작하는 걸 어려워한다 — "머보고 구현해? 아무 소스 없이?"
  → 뼈대·배선은 주고 **판단 자리만 `TODO(human)`**으로 비우는 형태가 맞았다 ([ADR 0002](../docs/adr/0002-implementation-mode.md) 개정)
- 전체 그림 없이 세부부터 들어가면 헤맨다. **파트 시작 전에 "이게 전체의 어디인지"를 먼저** 말해야 한다
- 메타인지를 중요하게 여긴다 — 본인이 먼저 "선행 학습하고 진행하면 메타인지가 잘 될 것 같다"고 제안했다

## 진행 규칙

- 한 번에 파일 하나, `TODO(human)` 2~3개까지
- 결정은 **저스트-인-타임** — 필요해지기 직전에. `docs/CURRENT.md`의 "결정을 미룬 것" 표가 시점을 관리
- 검증은 말이 아니라 **실행 결과**로. "돌아갑니다" 대신 출력을 보여준다
- 답을 바로 주지 않는다 (30분 룰). 단 요청하면 준다

## 이 워크스페이스에 대해

- teach 워크스페이스를 프로젝트 루트가 아니라 `learning/`에 뒀다.
  루트에 `lessons/`, `reference/`가 흩어지면 `backend/`, `docs/`와 섞여 지저분해서
- ~~`study/` 디렉토리~~ — **`/study`는 안 쓰기로 정리** (2026-07-30).
  학습 기록이 두 군데로 갈라지는 문제. teach 하나로 통일했다
- 미션이 이미 `docs/`에 상세히 문서화돼 있어 인터뷰 없이 `MISSION.md`를 추출했다.
  **사용자 확인 필요** — 특히 "Success looks like" 항목

## 학습 사이클 — 읽기 → 만지기 → 만들기 (2026-07-30 확정)

파트 하나마다 이 셋을 순서대로 돈다. `CLAUDE.md`의 "마일스톤 진행 순서" 0번에 박아뒀다.

| | 도구 | 산출물 |
|---|---|---|
| 읽기 | `/mattpocock-skills:teach` | `lessons/NNNN-*.html` |
| 만지기 | `/tycoon-sim` | `sims/NNNN-*.html` |
| 만들기 | 코드 | `TODO(human)` |

⚠️ **`/mattpocock-skills:teach`는 Claude의 스킬 목록에 안 뜬다.** 사용자가 직접 슬래시로 쳐야 한다.
Claude는 그 시점에 "이 명령을 치라"고 안내만 할 수 있다. 이것 때문에 `CLAUDE.md`에 적어뒀다.

**왜 두 번 통과시키나**: 레슨은 "왜 그런지", 시뮬레이터는 "정말 그런지"를 준다.
읽기만 하면 유창성 착각이 생긴다 — 읽을 땐 알겠는데 손에 안 남음.
**예측이 틀리는 경험**이 저장 강도를 만든다.

## 관찰된 것

- **간격이 벌어지면 통째로 까먹는다** (2026-07-30 사용자 보고).
  → `CLAUDE.md`에 "오랜만에 돌아왔을 때" 복습 루프를 넣었다.
  핵심: 레슨을 **다시 읽지 말고 퀴즈를 먼저 풀 것**. 읽으면 "아 맞다" 하고 넘어간다
- **후보를 안 주면 못 고른다** (M2 `002_time.sql`). "타입을 정하라"는 막혔고,
  "이 셋 중 하나 + 고르는 기준"으로 바꾸니 진행됐다.
  → `TODO(human)`은 **빈칸 채우기 + 후보 나열** 형태가 이 학습자에게 맞다

## 레슨보다 브리핑이 먼저다 (2026-08-21 관찰 → 규칙화)

**Lesson 09·10·11 에서 연속으로 "이해 안 간다"가 나왔다.** 세 번 다 같은 방식으로 풀렸다 —
Claude 가 채팅에서 **상황 → 왜 곤란한가 → 도구** 순서로 다시 설명한 뒤에야 붙었다.

원인은 학습자가 아니라 **레슨의 형식**이었다. 레슨이 회를 거듭할수록 길고 촘촘해졌고
(1차 출처 인용, 교차 링크 5개씩), 그건 **복습용으로는 좋지만 첫 이해에는 방해**다.
한 파일이 "이해시키기"와 "나중에 찾아보기" 두 역할을 다 하려다 둘 다 어중간해졌다.

→ `CLAUDE.md` 의 학습 사이클에 **0-a 브리핑**을 추가했다. 역할을 갈랐다:
**이해는 채팅이, 참조는 레슨이.**

⚠️ 그리고 **판단이 안 갈리는 자리에 레슨을 붙이지 말 것.** Lesson 11 이 그랬다 —
M5-6 의 결정이 사실상 정해져 있어서(인메모리는 원리적으로 탈락) 레슨의 명분이 약했고,
그게 "왜 하는지 모르겠다"로 나왔다.

📌 **사용자가 "모르겠다"고 두 번 이상 말하면 내용을 더 넣지 말고 형식을 의심할 것.**

## teach 호출 프롬프트 규격 (2026-08-25 — Lesson 12 에서 또 걸려서 고정)

`teach` 는 **플러그인**이라 스킬 파일을 못 고친다. 그래서 **호출하는 프롬프트 쪽에 게이트를 건다.**

**Lesson 12 에서 나온 불만 두 개** — 둘 다 형식 문제였고 둘 다 프롬프트로 막힌다:

| 불만 | 실제 원인 | 프롬프트의 어느 칸이 막나 |
|---|---|---|
| *"뜬금없는 도입부"* | 도입 장면의 숫자를 **Claude 가 지어냈다.** 안 돌려보고 썼다 | **② 실측** |
| *"이번 레슨에서 뭘 할지, 목표가 뭔지 없다"* | 제목 밑에 바로 장면. 왜 읽는지 모른 채 읽게 됨 | **④ 목표 블록** |

📌 **`code-trace` 는 같은 주제로 훨씬 나았는데, 그 스킬엔 "Phase 1 — 실측부터.
상상한 값을 그리지 마라"가 박혀 있기 때문이다.** 문제는 주제가 아니라 **순서**였다.
그래서 규격의 핵심이 ②다 — **레슨을 쓰기 전에 먼저 돌려본다.**

### 붙여넣을 템플릿

```
/mattpocock-skills:teach

① 주제 — <한 줄. "무엇을 판정/선택할 수 있게 되는가">
② 실측 — 이 파일들의 숫자만 쓴다: <scratch/*.json · 데모 출력 · RESOURCES.md 의 절>
   ⚠️ 도입 장면을 지어내지 마라. 실측이 없으면 레슨을 쓰기 전에 먼저 재라.
③ 갈림길 — <판단이 갈리는 자리. 답이 하나면 레슨 대신 브리핑으로 끝낸다>
④ 목표 블록을 제목 바로 밑에 넣을 것 (assets/style.css 의 .goal). 다섯 칸 고정:
   무엇을 / 왜 지금 / 끝나면(할 수 있게 되는 일 2~3개) / 안 다루는 것 / 분량
   "이해한다" 는 금지 — "고를 수 있다 · 구분할 수 있다 · 근거를 댈 수 있다"
⑤ 분량 — 120행 이내, 1차 출처 3개 이하, 퀴즈 2문
⑥ 워크스페이스는 learning/ · Lesson NN · 우리 코드 맥락: <파일:행>
```

⚠️ **③이 게이트다.** 채우다가 갈림길이 안 써지면 그건 레슨이 아니라 브리핑감이다
(Lesson 11 이 그랬다 — 답이 사실상 정해져 있었다).

⚠️ **②를 채우려면 대개 먼저 뭔가를 돌려야 한다.** 그게 비용처럼 보이지만
Lesson 12 에서 그 측정이 **레슨보다 값어치 있는 걸 뱉었다**
(`review-evasion` 거짓 양성 33% · 타임아웃 상수 13배 오차 · G6 dedup 근거).
**실측이 레슨의 재료를 넘어 프로젝트의 발견이 된다.**
