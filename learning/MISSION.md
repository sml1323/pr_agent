# Mission: 에이전트 시스템 설계 사고

## Why

PR 리뷰 멀티 에이전트를 M0부터 M8까지 직접 만들면서, **LLM 시스템을 어떻게 설계하는지**를 몸으로 익힌다.
가져갈 자산은 완성된 에이전트가 아니라 **설계 루프** — 무엇을 불변식으로 못 박고, 무엇을 나중에 정하고,
어디에 사람을 넣을지 판단하는 감각. 다음에 다른 에이전트 시스템을 설계할 때 그대로 쓰인다.

## Success looks like

- PR이 열리면 4개 에이전트가 리뷰하고, 확신 있는 건 자동 게시·애매한 건 사람 큐로 가는 시스템이 **실제로 돈다**
- 각 마일스톤에서 세 질문에 답할 수 있다 — **설계 근거 / 엣지 케이스 / 변경 영향**. 특히 세 번째
- "왜 여기서 X가 아니라 Y인가"에 영상이나 문서를 안 보고 답할 수 있다
- 정책 상수와 스키마 제약을 섞지 않는다 — 이런 종류의 경계를 스스로 알아본다

## Constraints

- **코드는 직접 타이핑.** Claude는 뼈대·배선만 주고, 설계 판단 자리는 `TODO(human)`으로 비운다 ([ADR 0002](../docs/adr/0002-implementation-mode.md))
- 몇 주 단위. 며칠이 아님 — 알고 받아들인 비용
- LLM 제공자는 OpenAI 하나. 초반 변수 축소
- 참고서(*Agentic Design Patterns*)는 **저스트-인-타임** — 마일스톤 직전에 해당 챕터만
- 파이썬은 알지만 LLM API는 처음

## Out of scope

- **M9~M12** — 신뢰성 심화, 비용 관측, 평가 하네스, 피드백 루프. 설계 문서로만 남긴다
- 프론트엔드 대시보드 과투자. HITL 큐가 보이는 최소한만
- 모델·제공자 교체 실험 (M11이 범위 밖이 되면서 같이 빠짐)
- 에이전트에게 구현을 시키는 워크플로 자체를 익히는 것 — 이 프로젝트의 목적이 아님
