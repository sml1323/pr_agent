리듀서는 합치는 법이 아니라
허가다

넷이 같은 칸에 동시에 쓰려 할 때, LangGraph 는 기본적으로 거부한다. 리듀서는 그 거부를 푸는 열쇠다.

이어지는 곳 Lesson 06 은 넷이 각자 뭘 못 봤나를 다뤘다. 이번엔 그 앞 문제다 — 넷이 결과를 어디에 놓나.

그리고 06 에서 네가 "superstep 이거는 헷갈리네" 라고 적은 것, 이 레슨이 그거다. 실측으로 답한다.

장면부터

회의실에 화이트보드가 하나 있다. 검토자 넷이 동시에 들어와서 각자 발견한 걸 적으려 한다. 보드에는 발견 이라는 칸이 하나 있다.

넷이 동시에 그 칸에 손을 뻗는다. 무슨 일이 일어나야 옳은가?

가능한 규칙결과맞나
마지막 사람이 이긴다셋의 발견이 사라진다❌ 누가 마지막인지도 정의가 없다
넷을 이어 적는다발견 넷이 다 남는다✅ 우리가 원하는 것
거부한다아무도 못 쓴다⚠️ 안전하지만 쓸모없다

LangGraph 의 기본값은 세 번째다. 그리고 그건 게으름이 아니라 설계다. 왜 그런지가 이 레슨의 전부다.

먼저 용어 셋

말뜻화이트보드 비유
state그래프가 굴리는 dict 하나화이트보드 전체
채널 (channel)state 의 키 하나보드에 그어진 칸 하나
superstep병렬 노드들이 도는 한 라운드사람들이 한 번에 들어오는 회차
리듀서 (reducer)한 칸에 값이 여럿 올 때 합치는 함수"이 칸은 이어 적으세요"라는 안내문

공식 정의는 이렇다 — "A super-step can be considered a single iteration over the graph nodes. Nodes that run in parallel are part of the same super-step, while nodes that run sequentially belong to separate super-steps." (LangGraph Graph API)

핵심 병렬이냐 순차냐는 코드 모양이 아니라 superstep 이 같으냐 다르냐로 갈린다. 같은 superstep = 동시. 다른 superstep = 순서 있음. 이 구분이 아래 모든 것을 결정한다.

실측 — 같은 코드, superstep 만 다르게

노드 a 는 ["A"] 를, 노드 b 는 ["B"] 를 같은 키 box 에 쓴다. 리듀서는 없다. 배선만 바꿔서 두 번 돌렸다. 

# 순차 —  START → a → b → END   (superstep 두 개)
A 순차 · 리듀서X → {'box': ['B']}          # 덮어썼다

# 병렬 —  START → a, b → END      (superstep 하나)
B 병렬 · 리듀서X → 💥 InvalidUpdateError
   At key 'box': Can receive only one value per step.

같은 노드, 같은 키, 같은 state 정의인데 결과가 다르다. 바뀐 건 배선 한 줄뿐이다.

왜 순차는 덮어쓰고 병렬은 터지나

공식 문서는 리듀서가 없을 때를 이렇게 말한다 — "If no reducer function is explicitly specified then it is assumed that all updates to that key should override it."

"덮어쓴다"가 성립하려면 누가 나중인지가 정해져야 한다. 순차에서는 정해진다 — b 가 a 뒤다. 그래서 ['B'].

그런데 같은 superstep 안에서는 "나중"이라는 게 없다. 넷이 동시에 도는데 누가 마지막인지 물으면, 답은 "그때그때 다름"이다. 그리고 그때그때 다른 답을 조용히 고르는 시스템은 디버깅이 불가능하다.

그래서 LangGraph 는 고르지 않고 거부한다.
"한 스텝에 값 하나만 받는다"는 그 뜻이다.

리듀서를 달면

from typing import Annotated
import operator

class S(TypedDict):
    box: Annotated[list, operator.add]   # ← 이 한 줄
C 병렬 · 리듀서O → {'box': ['A', 'B']}    # 이어붙었다

Annotated[list, operator.add] 는 파이썬 타입 힌트에 메타데이터를 붙이는 문법이다. 타입은 여전히 list 고, 옆에 달린 operator.add 는 파이썬이 무시하는 부가 정보다 — 그걸 LangGraph 가 읽는다. operator.add 는 + 연산자의 함수 버전이고, 리스트끼리 + 는 이어붙이기다.

이름이 오해를 부른다 "리듀서"라고 하면 합치는 방법처럼 들린다. 그건 절반이다.

나머지 절반이 더 중요하다 — 리듀서가 있다는 건 "이 칸에는 한 스텝에 값이 여럿 와도 된다"는 허가다. 허가가 없으면 합치는 방법 이전에 애초에 못 쓴다.

그래서 안 다는 것도 결정이다

그럼 전부 다는 게 안전한가? 아니다. 정확히 반대다.

키누가 쓰나리듀서안 달면
findings노드 넷이 동시에✅ 필수터진다 — 배선 즉시 실패
diff아무도 안 씀 (읽기만)❌ 안 단다—

diff 에 operator.add 를 달면 어떻게 되나. 평소엔 아무 일도 없다. 그런데 누군가 실수로 노드에서 {"diff": ...} 를 돌려주는 날, 터지는 대신 diff 가 두 배로 늘어난 채 조용히 흘러간다. 에이전트 넷이 두 배 길이의 diff 를 읽고, 토큰을 두 배 태우고, 없는 줄 번호를 가리킨다.

리듀서가 없다는 건 "여기 두 번 쓰면 잡아줘"라는 방어다.
"혹시 모르니 다 달아두자"는 그 방어를 스스로 해제하는 것이다.

정정 — 그리고 1차 출처 두 문장의 모순

이전 레슨 정정 · 2026-08-19 Lesson 06 노트 검토에서 이렇게 썼다 — "노드가 예외를 내보내면 성공한 결과까지 롤백".

절반만 맞다. 그리고 나머지 절반이 M5 설계를 바꾼다.

RESOURCES.md 에 적힌 1차 출처 인용 두 개가 서로 반대처럼 보인다:

인용읽으면
"the entire superstep is transactional. If any of these branches raises an exception, none of the updates are applied to the state."다 날아간다
"results from successful nodes within a superstep are saved, and don't repeat when resumed."안 날아간다

문서를 아무리 읽어도 안 갈린다. 그래서 돌렸다 — 병렬 노드 셋 중 하나만 raise, 체크포인터를 붙이고 저장소를 층별로 들여다봤다: 

실행된 노드              : ['c', 'boom', 'a']    # boom 이 중간에 터짐
체크포인트 channel_values : []                     # 커밋 안 됨
pending_writes           : [('box', ['docs'])]    # 끝난 c 만 남음
get_state().values       : ['docs']               # 둘을 합쳐 보여줌

재개 때 실행된 노드       : ['a', 'boom']          # c 는 안 돌고, a 는 다시 돎
둘 다 맞다. 층이 다르다.
채널(정식 체크포인트)에는 아무것도 커밋되지 않고,
이미 끝난 노드의 출력만 pending write 로 따로 남는다.

그런데 여기서 진짜 문제가 나온다. 같은 코드를 두 번 돌렸는데 결과가 달랐다. 한 번은 a 와 c 둘 다 남았고, 한 번은 c 만 남았다.

당연하다 — 남는 건 "터진 순간까지 끝나 있던" 노드뿐이고, 누가 언제 끝나는지는 그때그때 다르다. 실제로 두 번째 실행에서는 a 가 끝나며 write 를 저장하려는 순간 엔진이 이미 정리 중이라 cannot schedule new futures after shutdown 이 떴다.

그래서 결론이 뒤집히지 않는다 Lesson 06 의 처방 — 노드 안에서 try/except 로 실패를 값으로 바꿔라 — 은 그대로 유효하다. 오히려 근거가 더 강해졌다.

예외를 밖으로 내보내면 무엇이 살아남을지가 비결정적이다. 노드 안에서 잡으면 그 superstep 은 정상 종료하고, 넷의 결과가 전부 채널에 커밋된다 — 실패했다는 사실까지 값으로. 

# 실패를 값으로 바꾼 경우 — 정상 종료
box   : ['quality 결과', 'docs 결과']
failed: ['security: security 폭발']     # 이것도 함께 커밋된다

그리고 이게 resume() 이 성립하는 자리다. 재개할 때 이미 끝난 노드를 다시 부르지 않으니 INV-2 가 지켜진다 — 같은 리뷰에 LLM 호출이 두 번 안 나간다. 단, 체크포인터가 있을 때만이다. 없으면 저장할 곳 자체가 없다. M5-6 에서 체크포인터가 선택 사항이 아닌 이유다.

배운 법 자체 1차 출처 두 문장이 부딪힐 때, 더 읽어서는 안 갈린다. 돌려보고 층을 나눠 들여다봐야 갈린다.

이 레슨의 첫 정정도 실은 한 번만 돌려보고 쓴 것이라 부정확했다 — 두 번째 실행에서 결과가 달라지고 나서야 "타이밍에 달렸다"가 보였다. 한 번 돌아간 것은 근거가 아니다.
