예상한 실패와
우리 버그는 다르다

except Exception 하나로 뭉개면, 우리가 낸 오타가 "실패한 에이전트"로 위장한다.

06 의 짝 Lesson 06 은 "실패를 명단으로 남겨라" 였다. 이번은 그 앞 질문이다 — 무엇을 실패로 칠 것인가.

06 이 기록이면 09 는 분류다. 분류를 안 하면 명단이 거짓말을 한다.

장면부터 — 이 레슨을 쓰다가 실제로 당한 것

실측 코드를 짜면서 openai.RateLimitError 를 잘못 만들었다. 인자를 틀려서 AttributeError 가 났다. 그런데 출력은 이랬다: 

api    → 잡힘: AttributeError   → failed_agents 에 이름만 남는다

except Exception 이 내 오타를 "API 실패"로 보이게 만들었다. 레슨 주제를 시연하려던 코드가 주제 그 자체가 됐다.

이게 전부다. except Exception 은 실패를 다루는 게 아니라
실패인지 아닌지를 묻지 않는 것이다.

파이썬은 이미 같은 문제를 풀었다

Ctrl+C 를 눌렀는데 프로그램이 안 죽으면 곤란하다. 그런데 어딘가에 except Exception 이 있으면 그걸 삼켜버릴 것이다. 파이썬은 이걸 계층 구조로 풀었다 —

1차 출처 "[KeyboardInterrupt] inherits from BaseException so as to not be accidentally caught by code that catches Exception and thus prevent the interpreter from exiting."
— Python — Built-in Exceptions 

BaseException          # 여기는 아무도 안 잡는다
 ├── KeyboardInterrupt  ← 일부러 밖에 뒀다
 ├── SystemExit         ← 같은 이유
 └── Exception          # 여기부터가 "잡아도 되는 것"
      ├── TypeError
      ├── KeyError
      └── ...

"무엇을 잡을 것인가"는 우리가 처음 만나는 질문이 아니다. 파이썬 표준 라이브러리가 이미 답했고, 그 답이 계층이다. 잡히면 안 되는 것을 잡히는 것보다 위에 둔다.

OpenAI SDK 도 계층을 준비해뒀다

M6 에서 진짜 LLM 호출이 들어온다. 그때 던져질 예외를 지금 볼 수 있다 (SDK 가 이미 설치돼 있다): 

OpenAIError                       ← SDK 예외 전부의 뿌리
 ├── APIError
 │    ├── APIConnectionError
 │    │    └── APITimeoutError
 │    └── APIStatusError
 │         ├── RateLimitError
 │         ├── AuthenticationError
 │         └── InternalServerError · BadRequestError · ...
 ├── LengthFinishReasonError      # APIError 가 아니다
 └── ContentFilterFinishReasonError

주의 APIError 로 잡으면 전부가 아니다. LengthFinishReasonError(응답이 잘림)와 ContentFilterFinishReasonError(필터에 걸림)는 APIError 밑에 없다. 둘 다 우리에게 실제로 일어날 일이다 — 긴 diff 를 넣으면 응답이 잘리고, 공격적인 코드를 리뷰하면 필터에 걸린다.

실측 — 한 열이 전부를 가른다

잡는 범위APITimeoutAPIConnectionKeyError (우리 오타)Ctrl+C
except Exception잡힘잡힘잡힘 💥안 잡힘
except OpenAIError잡힘잡힘안 잡힘 ✅안 잡힘

가운데 두 열은 똑같다. 갈리는 건 세 번째 열 하나뿐이다. 그리고 그 하나가 "우리 버그를 볼 수 있느냐"를 정한다.

그런데 좁게 잡으면 그래프가 죽는다

여기가 진짜 긴장이다. 둘 다 나쁘다:

넓게 (Exception)좁게 (OpenAIError)
그래프✅ 안 죽는다❌ 버그 하나에 통째로 죽는다
우리 버그❌ "실패한 에이전트"로 위장✅ 드러난다
게이트가 보는 것커버리지 부족 (맞긴 함)아무것도 못 봄
답은 둘 중 하나가 아니다 —
잡는 것과 다루는 것을 분리하면 된다. 
try:
    finding = _call_agent(agent_type)
except OpenAIError:              # 예상한 실패
    ...                          # 명단에만 올린다
except Exception:                # 예상 못 한 것 = 우리 버그일 가능성
    ...                          # 명단 + "이건 버그다"를 어딘가 남긴다

except 절은 위에서부터 순서대로 맞춰본다. 그래서 좁은 것을 위에, 넓은 것을 아래에 둔다. 반대로 두면 넓은 게 먼저 잡아버려서 아래는 영영 안 돈다.

지금은 완전히 못 푼다 "어딘가 남긴다"의 어딘가가 M5 에 없다. M3 record_event 를 미뤘기 때문이다 (CURRENT.md 참조). 그래서 지금 할 수 있는 최선은 — 두 경우를 코드에서 갈라두고, 남길 자리가 생기면 채우는 것이다. 갈라두지 않으면 M3 가 와도 갈 수 없다. 이미 뭉개진 뒤라서.
