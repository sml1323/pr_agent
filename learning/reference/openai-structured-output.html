OpenAI Structured Output

pydantic 모델 → JSON schema → 강제된 출력. 필요할 때 꺼내 보는 치트시트.

기본 호출

from openai import OpenAI
from pydantic import BaseModel

client = OpenAI()   # OPENAI_API_KEY 환경변수를 자동으로 읽음

class Result(BaseModel):
    items: list[str]

completion = client.chat.completions.parse(
    model="gpt-4o-2024-08-06",
    messages=[
        {"role": "system", "content": "지시문 — 신뢰하는 쪽"},
        {"role": "user",   "content": "데이터 — 신뢰 못 하는 쪽"},
    ],
    response_format=Result,
)

msg = completion.choices[0].message
if msg.parsed:
    print(msg.parsed.items)
else:
    print(msg.refusal)     # 모델이 거부한 경우

response_format의 세 단계

흔한 혼동 — json_object는 "JSON이긴 하다"까지만 보장한다. 스키마는 보장하지 않는다.

값보장못 하는 것
{"type": "text"}
기본값		 없음—
{"type": "json_object"}
JSON Mode		 유효한 JSON이라는 것 키 이름·타입·구조 전부. 프롬프트에 "JSON"이란 단어가 반드시 있어야 함(없으면 API 에러)
{"type": "json_schema", "strict": true}
Structured Outputs — parse()가 쓰는 것		 스키마 구조까지 값이 사실인지

JSON Mode의 구멍 — 이것도 유효한 JSON이라 통과한다:

{"answer": "이 코드에 SQL 인젝션이 있습니다"}
# findings 배열도, confidence 필드도 없다. 파싱할 때 똑같이 터진다.

parse()에 pydantic 모델을 넘기면 SDK가 세 번째를 자동으로 조립한다:

# 내가 쓰는 것
response_format=ReviewResult

# SDK가 실제로 보내는 것
response_format={
    "type": "json_schema",
    "json_schema": {
        "name": "ReviewResult",
        "strict": True,
        "schema": { ...ReviewResult를 변환한 JSON schema... }
    }
}

.content vs .parsed

서버는 여전히 JSON 문자열을 보낸다. SDK가 그걸 pydantic 객체로 파싱해 넣어줄 뿐이다.

msg = completion.choices[0].message

msg.content   # '{"findings":[{"severity":"critical",...}]}'  ← 원본 문자열
msg.parsed    # ReviewResult(findings=[Finding(...)])         ← 파싱된 객체
msg.refusal   # 모델이 거부한 경우에만 채워짐. parsed 는 None
디버깅

.parsed가 이상하면 .content를 봐라. 원본 JSON을 봐야 모델이 이상한 값을 보낸 건지, SDK 파싱이 문제인지가 갈린다.

pydantic → JSON schema 대응표

pydanticJSON schema강제되나
str / int / float / bool type예
Literal["a", "b"] enum: ["a", "b"]예
list[Finding] array + items예
Field(ge=0.0, le=1.0) minimum / maximum예
Field(description="...") description아니오 — 모델이 읽고 참고할 뿐
중첩 BaseModel $defs + $ref예

걸리는 제약

  • 최상위는 반드시 객체. list[Finding]을 직접 못 준다 → ReviewResult처럼 한 겹 감싼다.
  • 모든 필드가 required. 선택 필드를 만들려면 Optional[X](= X | None)로 쓰고 모델이 null을 넣게 한다. "안 보내기"는 불가능하다.
  • additionalProperties: false가 강제된다. 스키마에 없는 키는 못 들어온다.
  • 지원 모델이 정해져 있다. gpt-4o-2024-08-06 이후 모델. 옛 모델은 json_object 모드까지만 된다(형식만 JSON, 스키마 강제 없음).

강제되는 것 / 안 되는 것

예시어떻게 다루나
형식 — 강제됨 타입, enum 값, 숫자 범위, 필드 존재 스키마에 쓰면 끝. 위반 불가
내용 — 강제 안 됨 confidence가 전부 0.9 · line 번호를 지어냄 · rationale이 diff에 없는 코드를 인용 description으로 유도 + 사후 검증 코드
이 프로젝트에서

"내용은 강제 안 됨"이 M6의 애그리게이터 검증(G1)과 M8 게이트가 존재하는 이유다. 스키마를 아무리 조여도 그럴듯하게 틀린 값은 통과한다.

자주 나는 에러

에러원인
Invalid schema: 'additionalProperties' is required to be false dict나 자유형 필드를 썼다. 구조를 명시적으로 정의할 것
root schema must be an object 최상위에 리스트를 줬다. 감쌀 것
message.parsed가 None 모델이 거부했다. message.refusal을 읽을 것
ValidationError (pydantic) 스키마로 못 나가는 제약을 걸었다. 예: min_length는 문자열에서 무시될 수 있음
