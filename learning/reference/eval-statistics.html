①Wilson score interval — 비율의 신뢰구간

무엇을 재나

"12판 중 8판 성공"이 진짜 성공률에 대해 무엇을 말하나. 관측한 p̂ = 8/12 는 표본이고, 알고 싶은 p 는 모집단이다. 신뢰구간은 그 간극의 크기다.

공식 — 그리고 Wald 와 무엇이 다른가

Wald (책 인쇄 221) p̂ ± z·√( p̂(1−p̂)/n ) p̂ + z²/2n ± z·√( p̂(1−p̂)/n + z²/4n² ) Wilson ─────────────────────────────────────────── 1 + z²/n z = 1.96 (95%)

차이는 한 곳뿐이다 — 분모(표준오차)에 무엇을 넣느냐. 둘 다 같은 부등식을 푼다:

| p̂ − p | ───────────── ≤ z SE Wald SE = √( p̂(1−p̂)/n ) ← 추정값 p̂ 를 박아 넣고 p 에 대해 푼다 (덧셈 한 번) Wilson SE = √( p(1−p)/n ) ← 미지수 p 를 그대로 두고 이차방정식을 푼다
면접에서 이렇게

"Wald는 표준오차 안에 추정값을 박아 넣습니다. 그래서 p̂ 가 0이나 1이면 p̂(1−p̂) = 0 이 되어 구간의 폭이 0이 됩니다 — '12판 다 성공했으니 성공률은 정확히 100%'라는 결론이죠. Wilson은 미지수 p 를 분모에 남긴 채 이차방정식을 풀기 때문에 경계에서도 구간이 무너지지 않습니다."

우리 숫자

측정WaldWilson결정에 미치는 영향
탐지 12/12[1.000, 1.000] 폭 0[0.757, 1.000] Wald면 "완벽"이라 더 잴 이유가 없다
오탐 0/3[0.000, 0.000] 폭 0[0.000, 0.562] D4가 정반대로 갈린다 — 아래
severity 8/12[0.395, 0.939][0.391, 0.862] 여기선 둘이 비슷하다
no_tag_rule 오탐 0/3 —
Wald 로 읽으면 "오탐 완전 해결", Wilson 으로 읽으면 "최대 56%까지 열려 있음".
같은 데이터, 정반대 결정.
⚠️ 언제 깨지나 / 책이 왜 Wald 를 줬나
책의 예시는 n=100, p=0.7 이다 — 거기선 Wald 가 잘 돈다. Wald 가 무너지는 조건은 n이 작거나 p̂가 0·1 경계에 붙을 때이고, 우리 데이터가 하필 둘 다다. Brown·Cai·DasGupta(2001)가 "standard interval을 쓰지 말라"고 못 박은 것이 정확히 이 구간이다.

②Pass@k / Pass^k — 그리고 불편추정량

무엇을 재나

같은 질문이 두 개라는 것이 이 공식의 전부다.

답하는 질문쓰는 곳
Pass@k"이 일을 할 수 있는가" — k번 중 하나 이상 성공 탐색적 능력 상한
Pass^k"안정적으로 신뢰할 수 있는가" — k번 모두 성공 비즈니스 신뢰성
Pass@k = 1 − (1 − p)^k Pass^k = p^k (책 인쇄 200)

우리 제1원칙("틀린 말을 안 하는 것")은 명백히 Pass^k 쪽이다. 그런데 우리 완료 판정은 전부 Pass@1 — 데모를 한 번 돌려 통과하면 ✅.

우리 숫자 (p̂ = 8/12)

Pass@k Pass^k k=1 66.7% 66.7% k=4 98.8% ←→ 19.8% PR 4건 연속 k=10 100.0% ←→ 1.7% PR 10건 연속

⚠️ 책이 안 다루는 것 — p 를 모를 때

p^k 는 p 를 알 때의 정의다. 우리는 p̂ 를 추정할 뿐이고, x ↦ x^k 가 볼록이라 젠센 부등식에 의해

E[ p̂^k ] ≥ ( E[p̂] )^k = p^k ← 거듭제곱하면 신뢰성을 과대평가

쓸 것은 비복원 추출 형태의 불편추정량이다:

C(c, k) pass^k = ───────────── c = 성공한 판 수 · n = 전체 판 수 C(n, k)
면접에서 이렇게

"n판 중 k판을 비복원으로 뽑았을 때 전부 성공일 확률입니다. 판들이 교환가능하므로 그 기대값이 '앞의 k판이 전부 성공일 확률', 즉 정확히 p^k 가 됩니다 — 그래서 불편입니다. p̂^k 를 쓰면 젠센 부등식만큼 위로 뜹니다. HumanEval 의 pass@k 추정량 1 − C(n−c,k)/C(n,k) 와 같은 계열이고요."

우리 숫자로 확인 (c=8, n=12)

kp̂^k (책)C(c,k)/C(n,k)과대
30.29630.25451.16배

편향을 해석적으로 확인 (p=2/3, n=12, k=3):

E[ p̂³ ] = 0.3328 참값 p³ = 0.2963 편향 = +0.0365 E[ C(c,3)/C(12,3) ] = 0.2963 편향 = +0.000000 ✅
⚠️ 반대 방향 함정
여러 픽스처를 합칠 때 집계 p̄ 를 거듭제곱하면 이번엔 과소평가다 (픽스처마다 p가 다르면 E[pᵢᵏ] ≥ p̄ᵏ, 같은 젠센이 반대로 작동).
→ 픽스처별로 먼저 계산하고 그 평균을 낸다. 절대 반대로 하지 않는다.
⚠️ 그리고 "판(trial)"이 무엇인지 아직 정의가 없다
k 가 (a) 에이전트 1회 호출의 반복인지 (b) ④⑤ 파이프라인 전체 실행의 반복인지가 우리 문서 어디에도 없다. 실측 12판은 (a) 인데 M6 완료 판정 대상은 (b) 다.
📖 책도 이걸 요구한다 (인쇄 200): "보고서에는 k가 독립 샘플인지 연속 프로덕션 작업인지 명시하고"

③McNemar 대응 검정 — 두 프롬프트 비교

무엇을 재나

"A 프롬프트가 B보다 낫다"가 신호인가 잡음인가. 두 성공률을 따로 재서 빼면 안 된다 — 같은 픽스처·같은 시드로 짝지어 돌린 뒤 불일치한 쌍만 센다.

B 성공 B 실패 A 성공 a b ← b: A만 맞힘 A 실패 c d ← c: B만 맞힘 a, d 는 버린다. n_d = b + c (불일치 쌍) H₀ 아래: b | n_d ~ Binomial(n_d, 0.5) 정확검정 양측 p = 2 · P( X ≤ min(b,c) ), X ~ Bin(n_d, 0.5)
면접에서 이렇게

"둘 다 맞힌 케이스와 둘 다 틀린 케이스는 정보가 없습니다 — 문제가 쉽거나 어려웠다는 뜻일 뿐이죠. 갈린 케이스만 보면 문제 난이도라는 공통 잡음이 빠집니다. 그래서 같은 표본 크기에서 독립 두 비율의 차이를 보는 것보다 훨씬 민감합니다."

⚠️ 검정 가능성 사전 검사 — 이게 실무 포인트다

불일치 쌍이 적으면 어떤 결과가 나와도 유의가 안 나온다. 한쪽 칸이 0일 때의 최소 양측 p 는 2 · 0.5^n_d:

n_d = 3 → 최소 p = 0.250 n_d = 4 → 0.125 n_d = 5 → 0.062 n_d = 6 → 0.031 ← 여기부터 α=0.05 를 넘길 수 있다
n_d < 6 이면 검정을 돌리지 마라.
답이 이미 정해져 있고, 돌리면 "유의하지 않다"를 "차이가 없다"로 오독하게 된다.
⚠️ 우리가 앞서 쓴 √2 근사에 대해
차이의 표준오차를 SE₁·√2 로 잡아 차이/SE = 0.87 을 계산했는데, 📖 책이 직접 단서를 단다 (인쇄 222): "앞의 √2 추정은 명백히 부족한 차이를 빠르게 거르기 위한 보수적인 기준일 뿐입니다."
→ 거름망으로만 쓴다. "차이 없음"의 증거로 쓰면 안 된다.

④다중 비교 — 아무것도 안 고쳐도 이기는 것이 나온다

무엇을 재나

가설을 여러 개 동시에 보면 우연히 이기는 게 반드시 나온다. 개별 신뢰수준이 95%여도, 독립인 가설 m개 전체에서 최소 1건이 거짓 양성일 확률은:

FWER = 1 − (1 − α)^m (family-wise error rate)

우리 숫자

프롬프트 3 × 픽스처 3 × 축 3(detected/severity/clean) = 가설 27개 1 − 0.95⁶ = 0.265 ← 책의 예시 1 − 0.95²⁷ = 0.750 ← 우리 설계
아무 개선이 없어도 4번 중 3번은 "어떤 프롬프트가 이겼다"가 나온다.

대응책이 둘이고, 값이 완전히 다르다

📖 인쇄 222 — "대응책은 가설 수에 따라 유의성 임계값을 강화하는 Bonferroni식 보정이나, 긍정적인 결과를 독립적인 확인 실행에서 재현할 때만 채택하는 것입니다."

무엇을비용
Bonferroniα = 0.05/27 = 0.0019 로 문턱을 올린다 필요 K가 폭증한다 — 비싸다
독립 재현이긴 하나만 새 시드로 다시 돌린다 훨씬 싸다 ✅
가설 줄이기축을 3 → 1(핵심 목표)로 좁힌다 1 − 0.95⁹ = 0.37 — 공짜
면접에서 이렇게

"27개 가설에 Bonferroni를 걸면 α가 0.0019가 되고, 그걸 넘기려면 표본이 몇 배로 듭니다. 실무에선 선별 단계는 느슨하게 두고, 이긴 후보만 독립 실행으로 재현시키는 쪽이 훨씬 쌉니다. 그리고 가설 수 자체를 줄이는 것도 대응책입니다 — '무엇을 안 재기로 할 것인가'가 설계 판단이죠."

⑤보정(calibration) — confidence 가 신호인가

무엇을 재나

"확신 90%"라고 말한 것들 중 실제로 90%가 맞나. 맞으면 보정됐다(calibrated)고 한다. 우리 INV-3 과 M8 게이트가 통째로 여기 걸린다.

Brier = (1/N) · Σ ( confᵢ − yᵢ )² yᵢ ∈ {0,1} ← 구간 나눌 필요 없음 ECE = Σ_b (n_b / N) · | acc(b) − conf(b) | ← 구간 b 로 나눠 가중 평균
면접에서 이렇게

"정확도(accuracy)와 보정(calibration)은 다른 축입니다. 전부 '확신 100%'라고 외치면서 70%만 맞히는 모델은 정확도는 괜찮아도 보정은 최악이고, 확신도를 게이트에 쓸 수 없습니다. Brier는 구간을 안 나눠도 되고, ECE는 신뢰도 다이어그램과 짝이라 '어느 구간에서 과신하나'를 볼 수 있습니다."

⚠️ 우리 데이터에 적용할 때 — 계획서의 오류를 여기서 잡았다

sql-injection 이 12판 전부 confidence=1.00 인 걸 보고 "확신도가 상수라 보정이 깨졌다"고 쓰기 쉬운데, 그건 틀렸다.

findingconfidence실제로 맞았나보정 관점
sql-injection1.00 × 12✅ 진짜 SQL 인젝션이다 완벽히 보정됨 — 확신 100%에 정답률 100%
review-evasion-attempt1.00❌ 정상 diff 였다 여기가 미보정

confidence 의 정의는 schema.py:52 에 있다 — "이 지적이 사실일 확률. 심각도와 무관하게 '내가 틀렸을 가능성'만 본다." severity 가 틀린 것은 confidence 의 관할이 아니다.

보정은 finding 하나짜리가 아니라 전체 finding 집합에서만 잴 수 있다.
그리고 각 finding 에 맞았다/틀렸다 라벨이 있어야 한다.

따라서 M6-0b(보정 재기)는 M6-0c(expected.yaml)에 의존한다. 라벨이 없으면 y_i 가 없고, y_i 가 없으면 Brier 도 ECE 도 계산이 안 된다. M6-PLAN.md 의 순서를 그렇게 고칠 것.

⚠️ 그리고 M6 에서는 답이 안 나올 가능성이 높다
보정 곡선을 그리려면 confidence 가 여러 값에 퍼져 있어야 하는데, 우리 관측은 대부분 0.9 이상에 몰려 있다. 구간이 하나뿐이면 곡선이 아니라 점 하나다.
그것 자체가 결과다 — "확신도가 신호가 아니라 거의 상수"라는 증거이고, 그게 📖 인쇄 291 "모델이 신뢰도 같은 값을 산출하더라도 검증 전 추정치일 뿐 승인 게이트의 근거로 사용하지 않습니다" 와 만난다 → D5.
